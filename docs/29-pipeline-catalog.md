# 파트 목록과 파이프라인 나누기

2026-11-10 · 상태: **적용함** — docs/28(리소스별 파이프라인)의 "기본(파트 표 순서)"를 고친다.

요청: "파트에 추가되었다고 기본 파이프라인에 추가되는 것은 맞지 않다. 전혀 근거 없는 파이프라인 설계가 되어 버린다(캐릭터 원화 → 캐릭터 모델링 → 애니메이션 → FX → 배경 원화 → 배경 모델링). 다른 툴들 검토하고 개선."

## 1. 무엇이 잘못됐나

docs/28은 파이프라인을 고르지 않은 리소스를 **기본(파트 표 순서)** 으로 계산하고, 화면에도 "기본" 파이프라인 카드로 **모든 사용 중 파트**를 표 순서대로 이어 보였다.

| 한 일 | 결과 |
|---|---|
| 파트 "배경 원화" · "배경 모델링" 더하기 | 파트 표 맨 뒤에 붙고, 곧바로 "기본" 파이프라인의 5 · 6단계(FX 다음)로 보인다 |
| | 아무도 정하지 않은 공정(FX → 배경 원화, 겹침률 0%)이 설계처럼 보인다 |
| 파트 표 순서 바꾸기 | 파트 목록의 보기 순서를 바꾸려다 공정 순서까지 바뀐다(두 뜻이 한 칸에) |

계산은 리소스가 거치는 파트만 이으므로 틀리지 않았지만, **파트 목록(어떤 팀 · 공정이 있나)** 과 **공정 순서(어떤 리소스가 어떤 차례로 거치나)** 가 한 표에 섞여 있어 화면이 사실과 다른 설계를 보여 준다.

## 2. 다른 도구

| 도구 | 단계 목록 | 공정(순서 묶음) | 새 단계를 만들면 |
|---|---|---|---|
| Kitsu(CGWire) | 전역 라이브러리의 **Task Type** 목록(부서 · 보기 순서) | 에셋 종류마다 쓰는 Task Type을 고른다. 공식 예: 캐릭터와 배경은 Task Type 파이프라인이 다르다(배경은 리그를 쓰지 않음) — [Pipeline Customization](https://kitsu.cg-wire.com/customization-pipeline/), [Getting Started](https://kitsu.cg-wire.com/configure-kitsu/) | 목록 맨 아래에 생길 뿐, 에셋 종류의 공정은 사람이 고른다 |
| ftrack | 시스템 설정의 **Task Type** 목록 | **Workflow Schema**(프로젝트 구조 템플릿)에 Task Type을 넣고, Task Template으로 묶는다 — [Creating a Workflow Schema](https://help.ftrack-studio.backlight.co/hc/en-us/articles/13129919596311-Creating-a-Workflow-Schema), [Task Templates](https://ftrack-python-api.readthedocs.io/en/master/example/task_template.html) | 스키마에 넣어야 쓰인다 |
| Flow Production Tracking(옛 ShotGrid) | **Pipeline Step** 목록 | 대상 종류마다 **Task Template**에 단계를 넣는다(docs/28 3절) | 템플릿에 넣어야 쓰인다 |
| Jira | 전역 **Status** 목록 | 이슈 종류마다 **Workflow**(Workflow Scheme) | 새 상태는 어느 워크플로에도 들어가지 않는다. 워크플로에 넣어야 쓰인다 — [Atlassian KB](https://support.atlassian.com/jira-align/kb/after-creating-new-statuses-in-jira-these-statuses-are-not-seen-in-jira-align/) |

공통점: **단계 목록(카탈로그)과 공정 템플릿을 나눈다. 새 단계는 목록에만 생기고, 어느 공정에 넣을지는 사람이 정한다.** "모든 단계를 목록 순서로 이은 숨은 기본 공정"은 없다.

## 3. 바꾼 것

| 곳 | 전 | 후 |
|---|---|---|
| 파트 표 | 순서 = 기본 공정 순서 | **파트 목록**. 순서는 화면에 보이는 순서일 뿐. 새 "파이프라인" 칸에 그 파트를 쓰는 파이프라인 이름, 없으면 "파이프라인 없음" |
| 공정 순서 · 파이프라인 | 숨은 "기본(파트 표 순서)" 카드 + 이름 붙인 파이프라인 | **이름 붙인 파이프라인만**. 어느 파이프라인에도 없는 사용 중 파트를 위에 알림("배경 원화 · 배경 모델링은 아직 어느 파이프라인에도 없습니다") |
| 새 파트 | 기본 공정 맨 뒤 | 파트 목록에만. 파이프라인에는 들어가지 않는다 |
| 리소스 | 파이프라인 비우면 파트 표 순서 | **늘 파이프라인 하나**. 새 리소스는 첫 파이프라인(고르기 칸으로 바꿈). 제작 리스트 가져오기로 생긴 리소스도 같다 |
| 새 프로젝트 | (파트 표 순서) | 마법사에서 정한 파트 순서로 파이프라인 "기본"을 만들고 모든 리소스에 준다 |
| 옛 파일 · 가져오기 | (파트 표 순서) | 파일 구조 **v11**: 파이프라인을 고르지 않은 리소스가 있으면 "기본" 파이프라인을 만들어 준다. 단계 = 그 리소스들이 **실제로 거치는 파트만**(파트 표 순서). 아무도 거치지 않는 파트는 넣지 않는다 → 그림의 배경 원화 · 배경 모델링은 들어가지 않는다 |
| 에셋 보드 | 파이프라인 고르기에 "기본(파트 표 순서)" | 파이프라인만("고르지 않음"은 그런 리소스가 남아 있을 때만) |
| 데이터 점검 E10 | 없는 파이프라인을 고른 리소스 | 파이프라인이 없거나 없는 파이프라인을 고른 리소스(주의, 그동안은 파트 표 순서로 계산) |

- 계산은 그대로다. 옮긴 "기본" 파이프라인의 단계 순서 = 파트 표 순서, 단계 겹침률은 비워 파트 쌍 값 → 설정의 기본 값을 물려받으므로 결과가 같다(옛 도구 비교로 확인).
- 파트 쌍 겹침률(시뮬레이션 · 옛 파일)은 단계 겹침률을 비운 단계가 물려받는 값으로 남는다. 직접 고치는 곳은 파이프라인 단계 사이 % 다.

## 4. 그림의 경우 쓰는 순서

1. 파트 표에 배경 원화 · 배경 모델링을 더한다 → "파이프라인 없음"으로 보인다.
2. 공정 순서 · 파이프라인에서 "배경"을 만들고 단계로 배경 원화 → 배경 모델링을 더한다.
3. 리소스 · 공수 표에서 배경 맵 · 프랍의 파이프라인을 "배경"으로 바꾼다 → 옮기기 창에서 원화 → 배경 원화, 모델링 → 배경 모델링(작업 진척 · 에셋 상태 함께).
4. "기본" 파이프라인은 이름을 "캐릭터"로 바꿔 캐릭터 · UI 리소스가 계속 쓴다.
