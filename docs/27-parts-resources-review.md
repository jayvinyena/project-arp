# 파트 · 리소스 공수 옮기기와 파트 순서 바꾸기 검토

2026-11-10 · 상태: **적용함**(추천안 전부, docs/28과 함께) — 결과는 6절.

요청: ① "배경 원화 · 배경 모델링 파트를 새로 만들어 배경 리소스 공수를 그쪽으로 할당하려는데, 기본으로 적용된 부분이 변경되지 않는다. 관련된 모든 로직 검토." ② "파트 순서 변경은 화살표보다 마우스로 일정 시간 누르면 행 전체를 옮기는 형태가 낫다. 전체 로직 검토."

## 1. 무엇이 막히나 (재현, 예시 파일)

| 한 일 | 결과 |
|---|---|
| 파트 "배경 원화" · "배경 모델링" 더하기 | 됨. 맨 뒤(FX 다음)에 붙고 모든 달 인원 0명 |
| 배경 맵 · 프랍의 새 파트 칸에 공수 넣기 | 됨 |
| 배경 맵 **모델링** 칸 비우기 | 됨 |
| 배경 맵 **원화** 칸 비우기 | **거절**: "이 파트에 작업 진척 기록이 있어 제외할 수 없습니다. 공수를 0으로 두십시오." — 배경 맵 원화에 완료 1개 기록이 있기 때문 |

즉 "기본으로 적용된 부분"(처음 만들 때 · 가져올 때 넣은 공수) 중 **작업 진척이 이미 쌓인 칸**은 비울 수 없다. 운영 파일은 대부분의 칸에 진척이 있어 사실상 옮길 수 없다. 안내 문구("0으로 두십시오")도 옮기려는 사람에게 맞지 않는다. 0으로 두면 그 파트를 거치는 것으로 남아 공정 · 겹침률 · 완료 판정에 계속 끼어든다.

AI 칸의 "=기본"은 **값이 아니라 안내 글**(AI 공수를 비우면 기본 공수를 그대로 쓴다)이다. 숫자를 넣으면 바뀌지만, 값처럼 보여 "바꿀 수 없는 칸"으로 오해하기 쉽다.

## 2. 공수를 다른 파트로 옮길 때 함께 따라가야 하는 것 (전체 로직)

리소스 하나가 파트 A(원화)에서 파트 B(배경 원화)로 옮겨 갈 때:

| 데이터 | 지금 | 옮기기에서 해야 할 일 |
|---|---|---|
| 기본 · AI 공수(efforts) | B에 새로 넣고 A는 비워야 함(A가 막힘) | A의 기본 · AI 공수를 B로(B에 이미 값이 있으면 B 값 유지 여부 선택) |
| 재작업률(resource_parts) | A에만 있음 | B로 |
| **작업 진척**(완료 수량 · 기준일 · 실투입 인·일) | A에 남아 A를 비울 수 없음 | **B로 옮긴다**(끝낸 원화 작업 = 끝낸 배경 원화 작업). B에 이미 기록이 있으면 더하기 · 기준일은 늦은 날 |
| **에셋 파트 상태**(완료 · 진행 · 담당 · 완료일 · Jira) | A에 남아 "계획 밖"으로 보임(파이프라인은 모든 파트) | B로 옮긴다. B에 이미 상태가 있는 에셋은 건너뛰고 알린다 |
| 유형 템플릿 · 물량 | 리소스 단위라 영향 없음 | — |
| 인력(파트 × 달) | B는 처음에 0명 → 계산상 B의 일은 끝나지 않음 | 옮긴 뒤 "배경 원화 인원 0명" 안내 + 인력 탭으로 가는 단추 |
| 겹침률(파트 쌍) | B와 이웃 파트의 쌍이 없어 기본 겹침률(설정)을 씀. **기준 정보 화면에 겹침률 고치는 곳이 없다**(시뮬레이션에서만) | 안내 + (선택) 기준 정보에 겹침률 칸 추가 |
| AI 비율(파트별) | B는 없음 → 기본 공수만 | 안내(필요하면 공수 보정 화면) |
| 작업자 소속팀 | 파트 이름 = 팀 → B가 팀 목록에 생김 | — |
| 현황판 · 에셋 보드 | 모든 파트가 열 · 칸으로 보임 | B가 추가 열로 보임(정상) |
| 변경 이력 | 칸마다 따로 남음 | **한 묶음**으로 남겨 한 번에 되돌림 |

## 3. 파트 순서를 바꿀 때 영향 (전체 로직)

파트 순서 = **공정 순서**다(앞 파트 → 뒤 파트). 순서를 바꾸면:

| 영향 받는 곳 | 내용 |
|---|---|
| 계산 엔진 | 리소스마다 거치는 파트를 이 순서로 잇고, 이웃 쌍의 겹침률을 쓴다. 쌍이 없으면 기본 겹침률. 순서를 뒤집으면 기존 쌍(예: 원화 > 모델링)이 쓰이지 않아 **데이터 점검 주의(P04)** 가 생긴다 |
| 에셋 단계 | 단계 = 앞에서부터 끝나지 않은 첫 파트. 이미 뒤 파트가 끝났는데 앞으로 옮긴 파트가 대기면 그 에셋은 앞 파트 단계로 보인다 |
| 작업 진척 확인 | "앞 공정보다 많이 끝난 칸"(주황) 검사가 새 순서로 다시 계산된다 |
| 화면 순서 | 보드 열 · 현황판 칸 · 인력 표 · 공수 표 · 소속팀 목록 · 시트 가져오기 파트 칸이 새 순서 |
| 지금 고치는 법 | ↑ · ↓로 이웃과 한 칸씩 맞바꾼다(여러 칸 옮기면 이력도 여러 묶음) |

## 4. 제안

### 4.1 공수 칸 비우기 → "옮기기 · 지우기" 창 (① 해결)

진척 · 에셋 상태가 있는 칸을 비우면 거절 대신 창을 연다.

```
배경 맵 · 원화에 기록이 있습니다
  작업 진척: 완료 1개(기준일 11/4)   에셋 상태: 3개(완료 2 · 진행 1)

  (●) 다른 파트로 옮기기  [배경 원화 ▾]   ← 이 리소스가 아직 거치지 않는 파트 우선
      공수 8 · AI · 재작업률 · 진척 · 에셋 상태를 함께 옮깁니다
  ( ) 기록까지 지우기(변경 이력에서 되돌릴 수 있음)
                                          [그만두기] [적용]
```

- 기록이 없는 칸은 지금처럼 바로 비운다.
- 각 칸에 마우스를 올리면 작은 **"옮기기"** 단추(→)도 보여, 비우지 않고 바로 옮길 수 있다.
- 적용 뒤 알림: "배경 맵을 원화 → 배경 원화로 옮겼습니다 · 배경 원화 인원 0명(인력에서 넣기)".
- 리소스 여러 개를 한 번에(배경 맵 · 프랍 → 배경 원화)는 같은 창에서 "같은 분류 모두"를 고른다(선택).

### 4.2 "=기본" 오해 줄이기

AI 칸이 비었을 때는 "=기본" 대신 흐린 **기본 값 숫자**(예: 8)를 보여 주고, 올리면 "AI 공수를 따로 넣지 않아 기본 공수를 씁니다. 숫자를 넣으면 AI 공수가 됩니다" 안내.

### 4.3 파트 순서: 눌러서 끌기 (② 해결)

| 항목 | 내용 |
|---|---|
| 잡기 | 행 왼쪽 **손잡이(⠿)를 누르거나**, 행을 **0.3초 길게 누르면** 행 전체가 떠오른다(입력 칸 · 체크 칸은 제외) |
| 끌기 | 끄는 동안 놓일 자리에 선 표시, 다른 행이 비켜 준다. Esc로 취소 |
| 놓기 | 한 번에 새 순서로(이력 한 묶음). ↑ · ↓ 단추는 없앤다 |
| 키보드 | 손잡이에 초점 → 스페이스로 잡고 ↑ · ↓ · 스페이스로 놓기(마우스 없이도) |
| 놓은 뒤 안내 | "공정 순서: 원화 → 배경 원화 → 모델링 …" + 영향(겹침률 쌍이 없는 이웃 n곳은 기본 겹침률 · 순서가 뒤집힌 겹침률 n개) |
| 같은 방식 | 배치 순서 · 업데이트 우선순위(지금 ↑ · ↓)도 같은 부품으로(선택) |

### 4.4 (선택) 기준 정보에 겹침률

파트 표 옆에 "이웃 파트 겹침률"(공정 순서대로 이웃 쌍, 비면 기본값)을 두어 새 파트 · 순서 변경 뒤 바로 고칠 수 있게 한다. 지금은 시뮬레이션에서만 바꿀 수 있다.

## 5. 정할 것

| 질문 | 추천 | 다른 안 |
|---|---|---|
| 1. 기록이 있는 칸 비우기 | **옮기기 · 지우기 창**(4.1) | 기록까지 지우기만 |
| 2. 옮길 때 진척 · 에셋 상태 | **새 파트로 함께 옮김** | 옮기지 않고 지움 |
| 3. 여러 리소스 한 번에 | 같은 분류 모두 옮기기 포함 | 한 리소스씩 |
| 4. 파트 순서 | **손잡이 · 길게 눌러 끌기**, 화살표 없앰, 키보드 지원 | 끌기 + 화살표 함께 |
| 5. 같은 끌기를 배치 · 업데이트 우선순위에도 | 함께(일관성) | 파트만 |
| 6. 기준 정보 겹침률 칸 | 넣음 | 지금처럼 시뮬레이션에서만 |

예상 크기: 4.1 ~ 4.3 하루, 4.4와 5번(배치 · 우선순위) 반나절.

## 6. 적용 결과 (2026-11-10)

| 제안 | 만든 것 | 곳 |
|---|---|---|
| 4.1 옮기기 · 지우기 창 | 기록(작업 진척 · 에셋 상태)이 있는 기본 공수 칸을 비우면 바로 거절하지 않고 창을 연다. 칸에 마우스를 올리면 보이는 **→** 로도 연다. "같은 분류 함께" 체크로 여러 리소스를 한 번에. 모두 이력 한 묶음이라 한 번에 되돌린다 | [MoveDialog.tsx](../web/app/ui/MoveDialog.tsx), [core/pipelines.ts](../core/pipelines.ts) `moveResourcePart` · `dropResourcePart` |
