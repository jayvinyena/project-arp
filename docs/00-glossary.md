# 용어 사전

ARP(아트 리소스 플래너) 새 설계에서 쓰는 말. 화면, 문서, 코드 주석은 모두 이 표의 이름을 쓴다.
괄호 안은 코드·DB에서 쓰는 이름이다.

## 계획 대상

| 용어 | 뜻 | 예 |
|---|---|---|
| 프로젝트 (project) | 계획 파일 하나가 다루는 게임 또는 제품. 파일 하나 = 프로젝트 하나 | `런칭A.arp` |
| 파트 (part) | 작업을 맡는 조직 단위. 공정 단계이기도 하다 | 원화, 모델링, 애니메이션, FX |
| 공정 순서 (part order) | 리소스 하나가 파트를 거치는 순서. 파트의 `순서` 값 오름차순 | 원화 → 모델링 → 애니메이션 → FX |
| 리소스 분류 (resource group) | 리소스 종류를 묶는 이름. 계산에는 쓰지 않고 표시·합계에만 쓴다 | 캐릭터, 배경, UI |
| 리소스 종류 (resource type) | 물량을 세는 단위가 되는 아트 결과물의 종류 | 신규 캐릭터, 코스튬, 프랍 |
| 스테이지 (stage) | 작업의 최소 단위. `업데이트 × 리소스 종류 × 파트` | 런칭의 신규 캐릭터 모델링 |

## 일정

| 용어 | 뜻 |
|---|---|
| 업데이트 (update) | 날짜가 있는 출시 묶음. 런칭도 업데이트의 한 유형이다 |
| 런칭 (launch) | 유형이 "런칭"인 업데이트. 프로젝트에 0개 또는 1개 |
| 업데이트 유형 (update type) | 업데이트의 종류. 기본 물량 템플릿을 가진다. 예: 런칭, 시즌, 미니 |
| 기본 물량 템플릿 (type template) | 유형별로 리소스 종류마다 정해 둔 최저·목표·확장 물량. 새 업데이트를 만들 때 복사한다 |
| 시작일 (start date) | 그 업데이트 작업을 시작할 수 있는 첫날 |
| 제작 완료 목표일 (content freeze date) | 아트 작업을 끝내야 하는 날. 없으면 출시일을 쓴다 |
| 출시일 (release date) | 사용자에게 나가는 날 |
| 우선순위 (priority) | 숫자 순위. 1이 가장 먼저. 인력을 나눌 때 먼저 배정한다 |
| 계획 기간 (planning horizon) | 계산하는 기간. 시작 월부터 끝 월까지. 인력은 이 기간 전체에 있어야 한다 |
| 근무 달력 (work calendar) | 근무 요일과 휴일 목록. 월별 근무일 수를 여기서 계산한다 |

## 물량

| 용어 | 뜻 |
|---|---|
| 최저 · 목표 · 확장 (min · target · stretch) | 한 업데이트에서 리소스 종류마다 만들 수량의 세 구간. 항상 `최저 ≤ 목표 ≤ 확장` |
| 물량 구간 (plan mode) | 계산에 쓸 구간. 최저안 · 목표안 · 확장안 |
| 필수 여부 (required level) | 필수(MUST) 또는 선택(OPTIONAL). 같은 우선순위 안에서 필수를 먼저 배정한다 |
| 외주 수량 (outsource qty) | 통째로 외부에 맡겨 내부 인력이 쓰이지 않는 수량 |
| 완료 수량 (completed qty) | 파트별로 이미 끝낸 수량. 실적 |
| 남은 수량 (remaining qty) | `물량 − 외주 수량 − 완료 수량`, 0 미만이면 0 |

## 공수와 인력

| 용어 | 뜻 |
|---|---|
| 공수 (effort) | 한 파트가 리소스 1개를 만드는 데 드는 인·일 |
| 인·일 (person-day) | 한 사람이 하루 일하는 양. 모든 공수와 작업 가능량의 단위 |
| 공수 프로필 (effort profile) | 공수 기준의 판. "기본"은 반드시 있고, "AI 사용 시" 같은 판을 더할 수 있다 |
| 재작업률 (rework rate) | 고쳐 다시 하는 비율. 공수에 `1 + 재작업률`을 곱한다 |
| 난이도 (difficulty) | 업데이트별로 특정 리소스가 평소보다 어렵거나 쉬운 정도. 1이 보통 |
| 재사용률 (reuse rate) | 기존 결과물을 고쳐 쓰는 비율. 공수에 `1 − 재사용률`을 곱한다 |
| 여유율 (buffer rate) | 예상 못 한 일을 위한 여유. 모든 필요 공수에 `1 + 여유율`을 곱한다 |
| 필요 공수 (required days) | 남은 수량을 끝내는 데 드는 인·일. 아래 식 |
| 인원 (headcount) | 파트·월별 정규 인원. 소수 가능(0.5 = 반달 또는 반일) |
| 가동률 (utilization) | 근무일 중 실제 제작에 쓰는 비율 |
| 생산성 (productivity) | 공수 기준 대비 속도. 1이 기준, 신규 인원이면 1보다 작다 |
| 외주 인력 (outsource days) | 파트·월별로 외부에서 받는 작업 가능량(인·일) |
| 지원 인력 (support days) | 다른 조직에서 잠시 받는 작업 가능량(인·일) |
| 작업 가능량 (capacity) | 파트·월별로 쓸 수 있는 인·일. 아래 식 |
| 부하율 (load rate) | `필요 공수 ÷ 작업 가능량` |
| 겹침률 (overlap rate) | 앞 파트가 `1 − 겹침률`만큼 진행되면 다음 파트를 시작할 수 있다. 0 = 끝난 뒤 시작, 1 = 바로 시작 |

### 식

```
필요 공수 = 남은 수량 × 공수(프로필) × 난이도 × (1 − 재사용률) × (1 + 재작업률) × (1 + 여유율)
작업 가능량 = 인원 × 근무일 수 × 가동률 × 생산성 + 외주 인력 + 지원 인력
근무일 수 = 그 달의 근무 요일 수 − 근무 요일에 걸친 휴일 수
```

## 시뮬레이션과 저장

| 용어 | 뜻 |
|---|---|
| 원본 (base data) | 파일에 저장된 계획 데이터 |
| 시나리오 (scenario) | 원본 위에 얹는 변경 묶음. 원본을 바꾸지 않는다 |
| 시나리오 변경 (scenario change) | `대상 표 · 대상 키 · 항목 · 값` 한 줄 |
| 반영 (apply) | 시나리오 변경을 원본에 옮겨 저장하는 일. 변경 이력이 남는다 |
| 데이터 버전 (data version) | 저장할 때마다 1씩 오르는 숫자. 충돌 확인에 쓴다 |
| 변경 이력 (change log) | 누가, 언제, 무엇을, 왜 바꿨는지 |
| 편집 중 표시 (edit lock) | 파일을 고치는 사람 이름과 시각. 다른 사람은 읽기 전용으로 연다 |
| 계산 불가 (blocked) | 데이터 문제로 결과를 낼 수 없는 상태. 숫자를 지어내지 않고 이유를 보여준다 |

## 쓰지 않는 말

| 쓰지 않음 | 대신 |
|---|---|
| 파이프라인, 인계 방식, 묶음 인계 | 공정 순서, 겹침률 |
| 캐파, Capacity | 작업 가능량 |
| 기준안, 베이스라인 (런칭을 뜻할 때) | 런칭 |
| 추가 · 취소 · 이월 수량 | 물량을 직접 고치고 변경 이력에 이유를 남긴다 |
| HIGH · MEDIUM · LOW 우선순위 | 숫자 순위 |
