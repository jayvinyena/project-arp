# 검증 규칙 v1

> 이 문서는 `rules/validation-rules.mjs`에서 만든다(`node tools/gen-rules-doc.mjs`). 직접 고치지 않는다.

## 등급

| 등급 | 뜻 |
|---|---|
| **오류** | 계산 불가. 모든 업데이트가 같은 인력을 나눠 쓰므로, 한 곳이 틀리면 다른 업데이트의 결과도 틀린다. 그래서 일부만 계산하지 않고 전체를 막고 이유를 보여준다. |
| **주의** | 계산은 하고 결과 옆에 표시한다. |

- 검사 대상 업데이트는 상태가 **계획** 또는 **진행**인 것만이다. 완료·취소 업데이트는 계산에도 검사에도 넣지 않는다.
- 시나리오 계산은 원본에 시나리오 변경을 얹은 데이터로 같은 규칙을 다시 돌린다(1단계 엔진).
- 표 형식(숫자 칸에 글자, 날짜 모양, 없는 ID 참조)은 저장 단계에서 막으므로 여기에 없다. [데이터 모델](01-data-model.md) 참고.

## 규칙 (36개: 오류 20 · 주의 16)

### 설정

| 코드 | 등급 | 문제 | 고치는 방법 |
|---|---|---|---|
| S01 | 오류 | 설정이 없다 | 프로젝트 설정에서 계획 기간과 근무 요일을 입력한다. |
| S02 | 오류 | 계획 기간이 거꾸로이거나 60개월을 넘는다 | 끝 월을 시작 월 이후로, 기간은 60개월 이내로 맞춘다. |
| S03 | 오류 | 설정 값이 범위를 벗어난다 | 여유율·기본 겹침률은 0–1, 부하율 기준은 0 < 주의 < 초과 < 심각, 근무 요일은 하루 이상, 늦음 기준은 0 이상. |

### 파트 · 공정

| 코드 | 등급 | 문제 | 고치는 방법 |
|---|---|---|---|
| P01 | 오류 | 사용 중인 파트가 없다 | 파트를 하나 이상 만들고 사용으로 둔다. |
| P02 | 오류 | 사용 중인 파트의 순서가 겹친다 | 공정 순서가 정해지도록 파트마다 다른 순서 번호를 준다. |
| P03 | 오류 | 겹침률이 0–1 밖이다 | 겹침률을 0(끝난 뒤 시작)부터 1(바로 시작) 사이로 고친다. |
| P04 | 주의 | 쓰이지 않는 겹침률 | 앞 파트가 공정 순서상 먼저 오도록 고치거나 행을 지운다. |

### 리소스 · 공수

| 코드 | 등급 | 문제 | 고치는 방법 |
|---|---|---|---|
| E01 | 오류 | 기본 공수 프로필이 없다 | 공수 프로필에 BASE(기본)를 만든다. |
| E02 | 오류 | 물량이 있는 리소스 종류가 거치는 파트가 없다 | 리소스 종류에 거치는 파트를 하나 이상 지정한다. |
| E03 | 오류 | 물량이 있는 리소스 종류에 기본 공수가 없다 | 그 리소스·파트의 기본(BASE) 공수를 입력한다. |
| E04 | 오류 | 공수가 0보다 작다 | 1개당 인·일을 0 이상으로 입력한다. 그 파트를 거치지 않으면 거치는 파트에서 빼거나 0으로 둔다. |
| E05 | 오류 | 재작업률이 0–1 밖이다 | 재작업률을 0–1로 고친다(0.1 = 10%). |
| E06 | 오류 | 공수 프로필 비율의 합이 1이 아니다 | 파트마다 프로필 비율을 0 이상, 합 1로 맞춘다. |
| E07 | 주의 | 섞어 쓰는 프로필의 공수가 일부 없다 | 그 프로필 공수를 입력하거나, 없으면 기본 공수를 쓴다는 것을 확인한다. |

### 업데이트

| 코드 | 등급 | 문제 | 고치는 방법 |
|---|---|---|---|
| U01 | 오류 | 시작일이 없다 | 업데이트 작업을 시작할 수 있는 날을 입력한다. |
| U02 | 주의 | 출시일이 없다 | 출시일을 입력한다. 없으면 완료 예정일만 보여주고 늦음 여부는 판단하지 않는다. |
| U03 | 오류 | 날짜 순서가 틀렸다 | 시작일 ≤ 제작 완료 목표일 ≤ 출시일로 맞춘다. |
| U04 | 주의 | 날짜가 계획 기간 밖이다 | 계획 기간을 늘리고 그 달들의 인력을 입력한다. |
| U05 | 오류 | 런칭이 둘 이상이다 | 런칭 유형 업데이트를 하나만 남기고 나머지는 다른 유형으로 바꾼다. |
| U06 | 주의 | 우선순위와 출시일이 같은 업데이트가 있다 | 인력 배정 순서를 정하려면 우선순위를 다르게 준다. 그대로 두면 표시 순서를 따른다. |
| U07 | 주의 | 물량이 없는 업데이트 | 유형 템플릿에서 물량을 채우거나 업데이트를 취소 상태로 둔다. |

### 물량

| 코드 | 등급 | 문제 | 고치는 방법 |
|---|---|---|---|
| V01 | 오류 | 물량 템플릿 세 개 중 빈칸이 있다 | 세 템플릿(기본 이름: 최소안·기본안·최대안)의 수량을 모두 입력한다. 나눌 필요가 없으면 세 값을 같게 둔다. |
| V02 | 주의 | 템플릿 수량이 1 ≤ 2 ≤ 3 순서가 아니다 | 보통은 템플릿1(최소안) ≤ 템플릿2(기본안) ≤ 템플릿3(최대안)으로 둔다. 일부러 다르게 둔 것이면 그대로 둬도 계산된다. |
| V03 | 오류 | 난이도·재사용률·외주 수량이 범위 밖이다 | 난이도 > 0, 재사용률 0–1, 외주 수량 0 이상. |
| V04 | 주의 | 외주 수량이 물량보다 많다 | 외주 수량을 템플릿3(최대안) 물량 이하로 고친다. 넘는 만큼은 계산에서 0으로 본다. |
| V05 | 주의 | 쓰지 않는 리소스 종류에 물량이 있다 | 리소스 종류를 사용으로 바꾸거나 물량을 지운다. |

### 작업 진척

| 코드 | 등급 | 문제 | 고치는 방법 |
|---|---|---|---|
| A01 | 오류 | 완료 수량이 음수다 | 완료 수량을 0 이상으로 고친다. |
| A02 | 주의 | 완료 수량이 세 번째 템플릿 물량보다 많거나 물량에 없다 | 물량을 늘리거나 작업 진척을 고친다. |
| A03 | 주의 | 거치지 않는 파트의 작업 진척 | 파트를 고치거나, 그 파트를 거치는 파트로 추가한다. |
| A04 | 주의 | 뒤 공정이 앞 공정보다 많이 끝났다 | 앞 공정 진척이 빠졌는지 확인한다. |

### 인력

| 코드 | 등급 | 문제 | 고치는 방법 |
|---|---|---|---|
| C01 | 오류 | 계획 기간 중 인력이 없는 달이 있다 | 빠진 달의 인력을 입력한다("마지막 달 값으로 채우기"를 써도 된다). |
| C02 | 오류 | 인력 값이 범위 밖이다 | 인원·외주·지원 0 이상, 가동률 0–1, 생산성 0보다 크게. |
| C03 | 주의 | 할 일이 있는데 작업 가능량이 계속 0인 파트 | 인원·외주·지원 중 하나를 넣는다. 그대로면 그 파트를 거치는 일은 끝나지 않는다. |

### 유형 템플릿

| 코드 | 등급 | 문제 | 고치는 방법 |
|---|---|---|---|
| T01 | 주의 | 유형 템플릿 물량이 비었거나 순서가 틀렸다 | 세 수량(최소안·기본안·최대안)을 채우고 보통은 작은 것부터 둔다. 이 템플릿으로 만드는 새 업데이트가 같은 값을 받는다. |

### 시나리오

| 코드 | 등급 | 문제 | 고치는 방법 |
|---|---|---|---|
| X01 | 주의 | 시나리오가 고치려는 대상이 원본에 없다 | 그 변경을 지우거나, 대상이 새로 생길 것이면 INSERT로 바꾼다. |
