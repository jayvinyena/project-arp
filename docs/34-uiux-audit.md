# UI/UX 전수 검사 (사용자 흐름 기준)

2026-11-11 · 상태: **1 ~ 4단계 고침(8절 추천안대로)** — 결과와 남은 것은 9절. 리소스 X 지우기 문제는 7절.

요청: "UIUX를 사용자 흐름에 맞도록 전수 검사하고 개선이 필요한 부분 검토해서 문서로 먼저. 디자인도 트렌드에 맞도록 같이. 이번에는 디테일에 몰두." + "리소스 공수 설계에서 X로 제거가 불가능(이펙트)."

## 0. 방법

| 단계 | 한 것 |
|---|---|
| 캡처 | [tools/ux-capture.mjs](../tools/ux-capture.mjs): 화면 14개 + 시작 · 새 프로젝트 · 에셋 보드 · 카드 창 · 배치 · 작업자 · 업데이트 상세 · 안내 패널 · 보기 모드 · 다크 모드를 **1440 · 390**으로(에셋 예시 파일). `samples/out/shots/ux/` |
| 흐름별 검토 | 세 묶음을 나눠 화면(두 폭)과 코드(빈 상태 · 오류 · 비활성 · 마우스 올림 · 키보드 · 확인 창)를 함께 봤다. A 처음 쓰기 · 기준 정보 손질, B 일상 운영 · 에셋 · 공유, C 계획 수정 · 시뮬레이션 · 마감 맞추기 |
| 확인 | "높음" 중 큰 것(A-06 기본 인원 덮어쓰기, A-22 옮기기 기본값 = 지우기, B-07 보기 모드 헛단추, C-02 배치 늦음인데 "바꿀 것 없음")은 코드로 다시 확인했다. 카드 창은 다시 캡처해 직접 봤다(D 항목) |
| 트렌드 | 2025 ~ 2026 B2B 도구 디자인 흐름(Linear 2026 화면 정리, 데이터 표 관행, SaaS 대시보드)과 비교(5절) |

## 1. 한눈에

| | 높음 | 중간 | 낮음 | 합 |
|---|---|---|---|---|
| A 처음 쓰기 · 기준 정보 | 6 | 25 | 14 | 45 |
| B 운영 · 에셋 · 공유 | 10 | 26 | 8 | 44 |
| C 계획 · 시뮬레이션 | 10 | 17 | 9 | 36 |
| D 카드 창 · 그 밖(직접) | 1 | 3 | 0 | 4 |
| **합** | **27** | **71** | **31** | **129** |

한 줄 결론: **기능은 갖췄지만 "보고 → 까닭 → 고치기"가 끊겨 있고, 같은 것을 화면마다 다르게 부르며, 지우는 동작이 안전하지 않고, 390px에서는 핵심 칸이 화면 밖이다.** 하나하나 고치기보다 **공통 기반(용어 · 형식 · 창 · 되돌리기 · 표 규칙)을 먼저 세우면** 129건 중 절반 가까이가 함께 풀린다.

## 2. 흐름별 막히는 곳 (가장 아픈 8가지)

| # | 흐름 | 막히는 곳 | 항목 |
|---|---|---|---|
| 1 | 계획 수정 | **늦음을 봐도 따라갈 길이 없다.** 업데이트 계획 머리는 "늦음 0개"인데 배치 줄은 "늦음 +14", 마감 맞추기는 "바꿀 것 없음"(배치를 보지 않음). 근거는 흐린 "FX · 신규 캐릭터"뿐, 마감 맞추기 · 시뮬레이션으로 가는 길이 없다 | C-01 ~ 04 |
| 2 | 일상 운영 | **처리할 것을 하나씩 처리할 수 없다.** 처리할 것 → 에셋 화면으로 넘어가 카드를 닫아도 현황판으로 돌아오지 않고, 돌아오면 탭이 처음으로. 마감 지남은 에셋 화면에서 거를 수도 없다 | B-02, B-03, B-20 |
| 3 | 기준 정보 | **데이터 점검 · 변경 이력이 내부 말을 보인다.** 규칙 코드 · DB 키(`settings.buffer_rate`, `target_qty`) · 원값(0.8), 고칠 곳으로 가는 단추 없음 → 막다른 길 | A-04, A-05 |
| 4 | 기준 정보 | **조용히 덮어쓰거나 지운다.** 기본 인원 수정 = 계획 기간 모든 달 덮어쓰기(달별 채용 계획 사라짐), 파이프라인 바꾸기 창 기본값 = 기록 지우기, 배치 · 썸네일 · 일괄 "완료" · "다 끝남"이 확인 없이 | A-06, A-22, B-04 ~ 06, B-33 |
| 5 | 계획 수정 | **바꾼 것과 결과가 이어지지 않는다.** 물량을 고쳐도 결과는 700px 위 카드에만, 전 · 후 비교 없음. 거꾸로 계산의 답(프랍 60 → 62, +1명)을 적용할 단추 없음, 시뮬레이션 "반영"이 비교보다 앞에 | C-05 ~ 07 |
| 6 | 처음 쓰기 | **새 파트를 계산에 넣기까지 숨은 3단계**(파트 표 → 파이프라인 → 인력), 마법사에서 배운 "파트 순서 = 공정 순서"가 만든 뒤에는 틀림, 기준 정보 화면엔 다음 단계 안내 없음 | A-08, A-10, A-11 |
| 7 | 전부(390) | **모바일에서 핵심 칸이 화면 밖.** 계획의 판정, 시뮬레이션의 시나리오 열, 에셋 리스트의 단계 · 상태, 담당별 숫자, 작업자 참여 스위치. 밀 수 있다는 표시 없음. 머리가 화면 높이만큼 늘어나는 화면도 | A-01, A-32, B-09, C-08, C-09 |
| 8 | 전부 | **같은 개념, 다른 말 · 형식.** 판정 6가지(목표 안 / 마감 안 / 맞춤, 못 끝남 / 못 끝냄 / 기간 밖), 차이 단위(일 / 영업일 / 없음), 날짜 형식 7가지, 파트 / 단계 / 공정 / 팀, 엑셀 단추 이름 7가지, "리소스명"이 에셋 코드 | C-16 ~ 18, B-24 ~ 27, A-29, D-02 |

## 4. 화면별 전체 목록

심각도: 높음 = 흐름이 막히거나 데이터를 잃을 수 있음, 중간 = 헷갈리거나 손이 더 감, 낮음 = 다듬기. "(추정)"은 화면에서 직접 확인하지 못한 것.
