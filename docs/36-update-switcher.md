# 업데이트 고르기 위계 올리기 (검토)

2026-11-11 · 상태: **추천안(A 업데이트 띠)대로 고침** — 결과는 5절

요청: "주요 메뉴 중 하나인 업데이트 부분의 위계가 낮아서 눈에 잘 띄지 않음. 개선할 수 있는 방안이 있는지 확인 필요."

## 1. 지금

"지금 업데이트"는 한 값을 여러 화면이 함께 쓴다(App `curUpdate`). 그런데 고르는 곳은 화면마다 따로 있고 모양 · 자리 · 이름이 다르다.

| 화면 | 자리 · 모양 |
|---|---|
| 제작 현황판 | 제목 오른쪽, 물량 템플릿 고르기 옆 작은 고르기(이름표 없음) |
| 에셋 제작 현황 | 오른쪽 끝, 흐린 글 "업데이트(마일스톤)" + 작은 고르기 |
| 작업 진척 | 오른쪽 끝, 위 작은 이름표 "업데이트" + 고르기, 기준일 칸과 나란히 |
| 시뮬레이션 | "업데이트 자세히 보기" 구역 안 고르기 |

문제:

1. **화면 전체의 대상**을 바꾸는 고르기인데 일반 입력 칸(높이 40, 글 14px)과 같은 무게. 제목(h1)보다 훨씬 약하다.
2. 자리 · 이름표가 화면마다 달라 "지금 어느 업데이트를 보고 있나"를 매번 찾아야 한다.
3. 고르기를 열기 전에는 다른 업데이트가 몇 개 있는지, 어느 것이 늦는지 보이지 않는다.
4. 제목은 "제작 현황판" · "에셋 제작 현황"처럼 화면 이름뿐이라, 캡처 · 공유했을 때 어느 업데이트인지 알 수 없다.

## 2. 제안

### A. 공통 "업데이트 띠"(추천)

업데이트를 쓰는 세 화면(제작 현황판 · 에셋 제작 현황 · 작업 진척) 맨 위, 제목 바로 위에 같은 모양의 띠를 둔다.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 업데이트  [● 런칭 ✓]  [ 시즌 1 ✓ ]  [ 미니 1 ✓ ]  [ 시즌 2 ▲ ]        출시 27년 6월 30일 │
│                                                       완료 예정 27년 5월 21일 ✓ 목표 안 │
└──────────────────────────────────────────────────────────────────────────────┘
 제작 현황판 · 런칭
 업데이트(마일스톤) 하나의 제작 상황입니다 …
```

- **탭(진행 중 · 예정 업데이트가 6개 이하)**: 이름 + 판정 기호(✓ ! ▲ ✕). 고른 탭은 강조색 바탕 · 굵게. 한 번 눌러 바꾼다 — 다른 업데이트가 몇 개이고 어느 것이 늦는지 늘 보인다.
- **7개 넘으면** 고른 것 + 앞뒤 몇 개만 탭, 나머지는 "더 보기 ▾"(완료 · 취소된 업데이트도 여기).
- 띠 오른쪽: 고른 업데이트의 출시일 · 완료 예정 · 판정(이름 붙은 값).
- 제목 뒤에 업데이트 이름: "제작 현황판 · 런칭".
- 띠는 세 화면에서 **같은 자리 · 같은 모양**, 지금 각 화면의 고르기는 없앤다(물량 템플릿 · 기준일 같은 화면 고유 설정만 제목 오른쪽에 남김).
- 390: 띠가 가로로 밀리는 탭(지금 화면 항목 가운데로), 출시 · 판정은 아래 한 줄.
- 시뮬레이션의 "업데이트 자세히 보기"는 그 구역만의 고르기라 그대로 두되, 같은 탭 모양을 쓴다.

### B. 사이드바 위 고르기

프로젝트 이름 칸 아래에 "업데이트 런칭 ▾"를 두어 모든 화면 공통으로.

- 장점: 한 곳 · 늘 보임.
- 단점: 사이드바는 4단계에서 "물러나게" 정리한 길 찾기 영역이라 다시 무거워진다. 업데이트와 상관없는 화면(기준 정보 · 인력)에서도 보여 헷갈린다. 390에서는 접힌 메뉴 안이라 안 보인다.

### C. 지금 자리 그대로 모양만 키우기

각 화면 고르기를 큰 글씨 · 강조 테두리로.

- 가장 작게 고침. 자리 · 이름표가 화면마다 다른 문제(2)와 다른 업데이트가 안 보이는 문제(3)는 그대로.

## 3. 판단

| | 눈에 띔 | 화면마다 같음 | 다른 업데이트 · 판정 보임 | 고칠 크기 |
|---|---|---|---|---|
| **A 업데이트 띠** | 높음(제목 위 · 탭) | 같음 | 보임 | 중(공용 부품 1개 + 세 화면 머리) |
| B 사이드바 | 중 | 같음 | 안 보임 | 중 |
| C 모양만 | 중 | 다름 | 안 보임 | 작음 |

## 4. 정할 것

| 정할 것 | 추천 | 다른 안 |
|---|---|---|
| 1. 방식 | **A 업데이트 띠** | B · C |
| 2. 띠를 둘 화면 | **제작 현황판 · 에셋 제작 현황 · 작업 진척** | + 업데이트 계획(목록 위에서 고른 업데이트 강조) |
| 3. 탭에 넣을 업데이트 | **진행 중 · 예정만(완료 · 취소는 "더 보기")** | 모두 |

## 5. 결과

- 공용 부품 [UpdateBar.tsx](../web/app/ui/UpdateBar.tsx): 제작 현황판 · 에셋 제작 현황 · 작업 진척 맨 위에 같은 띠. 진행 중 · 예정 업데이트는 탭(이름 + 판정 기호), 완료 · 취소는 "완료 · 취소 N개" 고르기, 오른쪽에 출시 · 완료 예정 · 판정(이름 붙은 값). 판정은 그 화면의 물량 템플릿 기준(현황판은 고른 템플릿, 에셋 · 작업 진척은 앱 공통 템플릿).
- 각 화면의 옛 업데이트 고르기는 없앴다. 제목 뒤에 업데이트 이름("제작 현황판 · 런칭", 강조색).
- 390: 탭 줄이 가로로 밀리고(고른 탭 가운데, 끝 흐림) 출시 · 판정은 아래 줄.
- 시뮬레이션 "업데이트 자세히 보기"의 고르기는 그 구역 전용이라 그대로 둠.
- 크롬 시험(e2e-flow): 띠 탭으로 고른 업데이트가 에셋 · 작업 진척 · 시뮬레이션에 이어짐, 제목에 이름, 탭마다 판정 기호 · 출시 · 완료 예정 · 판정. 전체 274개 통과, 글자 잘림 0.
