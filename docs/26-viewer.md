# 보기(뷰어) 영역 검토 — 많은 사람에게 공유 · 최신 소식 알리기

2026-11-10 · 상태: **① 보기 모드 + ② 소식 적용(추천안대로)** — 8절. ③ 스냅샷 · ④ 웹 링크는 제안 그대로.

요청: "에디팅할 수 있는 영역과 뷰어 영역이 별개로 존재해서, 뷰어로 많은 사람에게 내용을 공유하거나 최신 내용을 알릴 수 있는 부분이 필요."

## 1. 지금 있는 것

| 기능 | 내용 | 한계 |
|---|---|---|
| 파일 공유 | 팀 공유 드라이브에 `.arp` 파일 하나. 열면 그 파일을 직접 읽고 쓴다 | 보는 사람도 편집 화면 그대로 연다 |
| 읽기 전용 | 다른 사람이 편집 중(편집 중 표시 30분)일 때만 자동으로 읽기 전용 | 보는 사람이 **스스로 보기로 열 방법이 없다**. 아무도 편집하지 않으면 보는 사람이 편집 중 표시를 남겨 정작 편집자가 읽기 전용이 될 수 있다 |
| 열 때 변화 알림 | "지난번 본 뒤" 업데이트 완료 예정 변화 · 다른 사람이 고친 횟수(브라우저마다 기억) | 완료 예정만 본다. 에셋 진행 · 편집자가 전하고 싶은 말은 없다 |
| 보고용 엑셀 | 왼쪽 아래 "보고용 엑셀 내보내기" | 표 위주, 현황판 · 썸네일 없음 |

유지비 0 원칙(서버 없음, 데이터는 회사 드라이브 안)과 지금 구조를 유지하면서 보기 영역을 만드는 방법을 비교했다.

## 2. 방식 비교

| 방식 | 보는 사람이 하는 일 | 최신 반영 | 비용 · 운영 | 보안 | 판단 |
|---|---|---|---|---|---|
| **① 보기 모드(같은 앱 · 같은 파일)** | 앱 시작 화면 "보기로 열기" → 공유 드라이브의 파일 고르기(한 번 고르면 최근 파일에 남음) | 편집자가 저장하면 보는 화면이 자동으로 다시 읽음 | 0원, 서버 없음 | 드라이브 권한 그대로 | **추천** |
| **② 소식(공지 + 자동 요약)** | 보기 모드 첫 화면에서 "새 소식" 확인 | 편집자가 쓰는 즉시 · 저장 후 | 0원 | 파일 안 | **추천(①과 함께)** |
| ③ 공유용 스냅샷(HTML 파일 한 장) | 메일 · 메신저로 받은 파일을 브라우저로 열기(앱 · 드라이브 권한 필요 없음) | 내보낸 그 순간 기준(기준 시각 표시) | 0원 | 파일을 받은 누구나 볼 수 있음(전달 범위 주의) | 선택(드라이브 권한 없는 사람용) |
| ④ 웹 링크(서버에 올려 공유) | 링크만 누르면 최신 화면 | 실시간 | 저장 공간 · 로그인(Cloudflare Access 등) 설정과 관리 필요 | 사내 자료가 회사 드라이브 밖 서버로 나감 → 보안 승인 필요 | 지금은 보류 |

비슷한 도구의 방식: 구글 시트 · 노션 · 피그마는 "같은 원본, 편집자/보기 권한"으로 나누고, 보고용 BI 도구는 "게시된 보기 화면 + 변경 알림"을 따로 둔다. ARP는 서버가 없으므로 **같은 파일 + 보기 모드 + 파일 안 소식**이 같은 효과를 내는 가장 작은 방법이다.

## 3. 제안 — ① 보기 모드

| 항목 | 내용 |
|---|---|
| 여는 법 | 시작 화면에 **"보기로 열기"**(편집 열기와 나란히). 최근 파일 목록에서도 "보기"로 열 수 있다. 주소 `?view`로 열면 늘 보기 모드(팀 위키 · 북마크에 걸어 둠) |
| 파일에 쓰지 않음 | 편집 중 표시를 남기지 않고, 자동 저장 · 복구 사본도 만들지 않는다 → 편집자를 막지 않는다 |
| 메뉴(보기 전용) | **소식 · 제작 현황판 · 에셋(보드 · 리스트 보기) · 업데이트 일정**. 계획 · 기준 정보 · 기록은 숨긴다 |
| 화면 | 모든 입력 칸 · 끌어 옮기기 · 만들기 단추를 감추고 값만 보여 준다(같은 화면 부품을 읽기 전용으로) |
| 최신 반영 | 1분마다 · 창으로 돌아올 때 파일 수정 시각을 확인해 바뀌었으면 다시 읽고 "방금 최신으로 바꿈(14:32 저장본)" 표시 |
| 위쪽 띠 | "보기 모드 · 마지막 저장 2026-11-10 14:32 · 편집: 홍길동" + (권한이 있으면) "편집으로 열기" |
| 필요 조건 | 크롬 · 엣지(파일 다시 읽기), 공유 드라이브 읽기 권한. 드라이브를 PC에 동기화(구글 드라이브 데스크톱 등)해 둔 사람 |

## 4. 제안 — ② 소식

"최신 내용을 알리는" 곳. 보기 모드의 첫 화면이고, 편집 화면에도 메뉴 하나로 둔다.

| 구성 | 내용 |
|---|---|
| **편집자 소식** | 편집자가 짧은 글(제목 · 내용 · 중요 표시)을 쓴다. 예: "M4 원화 2주 당김, 동료쿠키 3종 추가". 파일에 남아 누구나 본다(파일 구조에 표 하나 추가) |
| **자동 요약** | 지난번 본 뒤 바뀐 것을 자동으로: 업데이트 완료 예정 변화(지금 있는 알림 확장) · 새로 완료된 에셋 수 · 검수 요청 · 마감 지남 · 물량 변경 |
| 새 소식 표시 | 보는 사람마다 "마지막으로 본 소식"을 브라우저에 기억 → 메뉴에 "소식 3" |
| **알리기 문구 복사** | 소식 하나(또는 이번 주 요약)를 메신저 · 메일에 붙일 글로 복사: 핵심 숫자 + "ARP 보기 모드에서 확인". 서버 없이 알림을 대신한다 |

## 5. 선택 — ③ 공유용 스냅샷

드라이브 권한이 없는 사람(경영진 · 다른 부서)에게 보낼 때: "보기용 파일 내보내기" → 현황판 · 에셋 목록(썸네일 포함) · 업데이트 일정 · 최근 소식을 담은 **HTML 파일 한 장**. 인터넷 없이 열리고 고칠 수 없다. 내보낸 시각을 크게 표시해 옛 자료로 헷갈리지 않게 한다. 받은 사람 누구나 볼 수 있으므로 전달 범위는 보내는 사람이 정한다.

## 6. 정할 것

| 질문 | 추천 | 다른 안 |
|---|---|---|
| 1. 만들 범위 | **① 보기 모드 + ② 소식** 먼저, ③ 스냅샷은 그다음 | ①만 / ①②③ 함께 |
| 2. 보는 사람의 파일 접근 | 공유 드라이브 읽기 권한(지금 방식 그대로) | 드라이브 권한 없이 → ③이나 ④가 필요 |
| 3. 보기 메뉴 | 소식 · 현황판 · 에셋 보기 · 업데이트 일정 | 현황판만 |
| 4. 소식 쓰는 사람 | 편집하는 사람 누구나(이름 자동) | PM만(이름 목록으로 제한, 서버가 없어 강제는 못 함) |
| 5. ④ 웹 링크 | 보류(보안 승인 · 운영 부담) | 필요하면 별도 설계 문서로 |

## 7. 만들 때 순서(정하면)

1. 보기 모드: 여는 법 · 파일에 쓰지 않기 · 보기 메뉴 · 입력 감추기 · 자동 다시 읽기 · 위쪽 띠
2. 소식: 파일 구조 v8(소식 표, core/tables.ts에 한 줄) · 편집자 쓰기 · 자동 요약 · 새 소식 수 · 알리기 문구 복사
3. 시험: 보기 모드가 파일에 아무것도 쓰지 않는지(편집 중 표시 · 저장 없음), 편집자가 저장하면 보는 화면이 바뀌는지, 소식 · 새 소식 수, 보기 메뉴에 입력 칸이 없는지
4. (선택) 스냅샷 HTML

예상 크기: 1 + 2 + 3 하루 안팎.

## 8. 적용 결과 (2026-11-10)

| 항목 | 적용 |
|---|---|
| 여는 법 | 시작 화면 **"보기로 열기"**, 최근 파일마다 **"보기"** 단추(읽기 권한만 묻는다), 주소 `?view` |
| 파일에 쓰지 않음 | 보기 모드는 편집 중 표시 · 자동 저장 · 저장 단추 · 복구 사본이 없다. 닫아도 남의 편집 중 표시를 지우지 않는다 |
| 보기 메뉴 | 보기: 소식 · 제작 현황판 · 에셋 제작 현황 · 업데이트 계획. 다른 화면으로 가는 단추를 눌러도 현황판으로. 기존 읽기 전용 처리로 모든 입력 · 끌기 · 만들기가 잠긴다 |
| 처음 화면 | 새 소식이 있으면 소식, 없으면 제작 현황판 |
| 최신 반영 | 1분마다 · 창으로 돌아올 때 파일 수정 시각을 보고, 바뀌었으면 다시 읽어 "최신 저장본으로 바꿨습니다(14:32 저장)" |
| 위쪽 띠 | "보기 모드 · 마지막 저장 … · 지금 ○○님이 편집 중" + "편집으로 열기"(쓰기 권한을 묻고 편집으로 다시 연다) |
| 소식 | 메뉴 **소식**(편집: 현황 묶음 끝, 보기: 맨 위), 새 소식 숫자. 소식 쓰기(제목 · 내용 · 중요) → 소식 목록(새 소식 · 중요 표시) → 지난번 본 뒤 바뀐 것(변경 · 완료된 에셋 작업 · 새 에셋 · 검수 요청 · 수정 · 완료 예정) |
| 알리기 | 소식마다 "알리기 문구 복사", 요약에 "요약 문구 복사" — 프로젝트 이름 · 제목 · 내용 · 완료 예정 · "보기 모드에서 확인" |
| 파일 구조 v8 | `news(news_id, at, author, title, body, important)`. core/tables.ts에 한 줄(유지보수 B 덕분에 표 더하기가 두 곳만 고치면 됨) |
