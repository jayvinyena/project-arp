# 리소스별 파이프라인(공정 순서) 검토

2026-11-10 · 상태: **적용함**(추천안 B, docs/27과 함께) — 만든 것과 설계에서 바꾼 점은 8절.

요청: "리소스의 종류에 따라 파트의 순서를 설정할 수 있는 부분이 적용되어 있는지 확인하고, 없으면 리소스별로 파이프라인을 설계하는 부분 검토."

## 1. 확인 결과: 없다

| 무엇을 리소스마다 정하나 | 지금 |
|---|---|
| 거치는 파트 | **된다.** 리소스 · 공수 표에서 기본 공수를 넣은 파트만 거친다(비우면 안 거침) |
| 파트 순서(공정 순서) | **안 된다.** 프로젝트 전체에 순서가 하나(기준 정보 › 파트 표의 순서). 모든 리소스가 그 순서에서 자기가 거치는 파트만 골라 쓴다 |
| 겹침률(앞 공정이 얼마나 끝나면 다음 시작) | **안 된다.** 파트 쌍(예: 원화 > 모델링)마다 하나, 모든 리소스 공통. 쌍이 없으면 설정의 기본 겹침률 |
| 에셋 단계 순서 | 전체 파트 순서 하나(docs/20 20절: 모든 에셋이 같은 파이프라인) |

그래서 지금은:
- 캐릭터(원화 → 모델링 → 애니 → FX)와 배경(배경 원화 → 배경 모델링)은 **파트가 다르면** 각자 순서대로 돈다. 배경 파트를 어디에 두든 배경 리소스끼리의 순서만 맞으면 된다.
- 하지만 **같은 파트를 다른 순서로** 쓰는 리소스(예: 이펙트는 FX → 원화 마무리, UI는 원화 → FX → 모델링)는 표현할 수 없다.
- 같은 쌍이라도 리소스마다 겹침률이 다른 경우(캐릭터 원화 > 모델링 20%, 프랍 원화 > 모델링 60%)도 표현할 수 없다.
- 파트 표 순서를 바꾸면 모든 리소스의 순서가 한꺼번에 바뀐다(docs/27 3절).

## 2. 공정 순서를 쓰는 곳(전체)

| 곳 | 쓰는 방식 | 리소스별 파이프라인이 되면 |
|---|---|---|
| 계산 엔진 [engine/stages.ts](../engine/stages.ts) | 리소스가 거치는 파트를 전체 순서로 정렬해 앞 단계 → 다음 단계, 이웃 쌍 겹침률 | 리소스의 파이프라인 단계 순서 · 단계 겹침률 |
| 데이터 점검 P04 | 전체 순서와 반대인 겹침률 쌍 = 주의 | 파이프라인 단계 검사로 바꿈 |
| 에셋 단계 · 보드 · 단계 옮기기 [core/assets.ts](../core/assets.ts) | 모든 파트, 전체 순서 | 그 에셋 리소스의 파이프라인 순서 |
| 현황판 단계 분포 · 배치 진행 [core/dashboard.ts](../core/dashboard.ts) | 전체 순서 | 리소스별 순서 |
| 작업 진척 "앞 공정보다 많이 끝남"(주황 칸) | 전체 순서의 앞 파트 | 파이프라인의 앞 단계 |
| 리소스 · 공수 표, 인력 표, 현황판 칸, 소속팀 목록, 시트 가져오기 파트 칸 | 표시 순서 | 그대로(파트 목록 순서) |
| 시뮬레이션 겹침률 바꾸기 | 파트 쌍 | 파이프라인 단계(또는 쌍) |
| 옛 도구 비교(compare-legacy) | 옛 엔진과 같은 순서 | 옮긴 기본 파이프라인이 지금과 **같은 결과**여야 함(검사로 확인) |

## 3. 비슷한 도구

- Autodesk Flow Production Tracking(옛 ShotGrid): **Task Template**에 파이프라인 단계(Step)를 넣고, 템플릿은 대상 종류(에셋 · 샷)마다 따로 만든다. 에셋을 만들 때 템플릿을 고르면 그 단계들이 태스크로 생긴다. — [Create a Shot with a Task Template](https://developers.shotgridsoftware.com/python-api/cookbook/examples/basic_create_shot_task_template.html), [pipeline steps per entity type](https://community.shotgridsoftware.com/t/shots-pipeline-steps/18503)
- Kitsu: 작업 종류(Task Type)를 대상 종류에 "전용"으로 묶는다 — [Kitsu task types](https://www.mintlify.com/cgwire/kitsu/tasks/task-types)

공통점: **단계 목록(템플릿)을 이름 붙여 만들어 두고, 대상 종류가 하나를 고른다.** 단계 자체(파트 = 팀 · 인력)는 공통으로 둔다.

## 4. 설계안 비교

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 리소스마다 순서 | 리소스 행마다 파트 순서를 직접 끌어서 정함 | 가장 자유로움 | 리소스가 20 ~ 30종이면 같은 순서를 여러 번 반복 · 고칠 때 전부 고쳐야 함 |
| **B. 파이프라인 템플릿(추천)** | "캐릭터 파이프라인", "배경 파이프라인"처럼 이름 붙인 **단계 목록(순서 · 단계별 겹침률)** 을 만들고, 리소스는 하나를 고른다 | 비슷한 도구와 같은 방식. 같은 공정을 한 번만 정의 · 한 곳만 고치면 모두 바뀜. 에셋 보드도 파이프라인별로 열을 보여 줄 수 있음 | 표 하나 · 화면 하나 늘어남 |
| C. 지금처럼 전체 순서 하나 | 파트 표 순서만 | 단순 | 같은 파트를 다른 순서로 못 씀 |

## 5. 추천안 B 자세히

### 5.1 데이터(파일 구조 v10)

| 표 | 칸 | 뜻 |
|---|---|---|
| `pipelines` | pipeline_id, name, sort_order | 파이프라인 이름 · 순서 |
| `pipeline_steps` | pipeline_id, part_id, seq, overlap_rate(비우면 기본) | 단계 = 파트, seq = 순서, 겹침률 = 앞 단계와 겹치는 정도 |
| `resource_types.pipeline_id` | (새 칸) | 이 리소스가 쓰는 파이프라인 |

- 리소스의 **거치는 파트 = 파이프라인 단계 중 기본 공수를 넣은 것**(지금처럼 공수 칸으로). 파이프라인 밖 파트에는 공수를 넣을 수 없게(칸 잠금 + "파이프라인에 없는 파트" 안내).
- 파트 표의 순서는 **표시 순서**로만 쓴다(공정 순서 아님). → docs/27의 "파트 순서 바꾸기" 영향이 화면 순서로 줄어든다.

### 5.2 옮기기(기존 파일)

리소스마다 지금의 "거치는 파트를 전체 순서로 정렬한 목록"을 만들고, **같은 목록끼리 파이프라인 하나**로 묶는다(이름 = 그 리소스들의 분류 이름, 예: "캐릭터", "배경"). 겹침률은 지금 파트 쌍 값을 단계에 복사. → 계산 결과가 지금과 **완전히 같아야** 하고, 단위 검사 · 옛 도구 비교로 확인한다.

### 5.3 화면

| 곳 | 내용 |
|---|---|
| 기준 정보 › **파이프라인**(새 묶음, 파트 표 아래) | 파이프라인 카드마다 단계 칩을 끌어서 순서 바꾸기(docs/27의 눌러 끌기와 같은 부품), 단계 사이에 겹침률(%), 파트 더하기 · 빼기, 이 파이프라인을 쓰는 리소스 수 |
| 리소스 · 공수 표 | 리소스마다 **파이프라인** 고르기 칸. 파이프라인 밖 파트 칸은 잠금. 파이프라인을 바꾸면 docs/27의 **옮기기 창**(빠지는 단계의 공수 · 진척 · 에셋 상태를 새 단계로 옮기거나 지우기) |
| 에셋 카드 체크리스트 | 그 리소스 파이프라인 순서의 단계. 파이프라인 밖 파트는 "다른 파트 켜기"로만(지금의 "계획 밖") |
| 에셋 보드 | 위쪽에 **파이프라인 고르기**: 하나를 고르면 열 = 그 파이프라인 단계. "모두"면 지금처럼 전체 파트 순서 |
| 현황판 | 단계 분포를 파이프라인별로 묶어 표시 |
| 시뮬레이션 | "겹침률" 바꾸기의 대상이 파이프라인 단계(또는 모든 파이프라인의 그 쌍) |
| 새 프로젝트 마법사 | 파트를 정하면 기본 파이프라인 하나(모든 파트, 그 순서) 자동 |

### 5.4 규칙 · 검사

- 파이프라인 단계는 파트 하나를 한 번만. 단계가 하나도 없는 파이프라인은 리소스가 고를 수 없음.
- 데이터 점검: 리소스에 파이프라인이 없음(오류) · 파이프라인 밖 파트에 공수(오류) · 쓰지 않는 파이프라인(주의). P04는 파이프라인 단계 검사로 바꿈.
- 에셋 상태 · 작업 진척 · 공수는 파트 기준 그대로라, 파이프라인 순서를 바꿔도 기록은 유지되고 단계 판정만 새 순서로.

### 5.5 docs/27과의 관계

| docs/27 제안 | 파이프라인이 생기면 |
|---|---|
| 공수 옮기기 창 | 그대로 필요(파이프라인 바꾸기 · 단계 빼기에서도 같은 창을 씀) |
| 파트 순서 눌러 끌기 | **파이프라인 단계 순서**에 쓰는 것이 핵심. 파트 표는 표시 순서라 끌기는 있어도 되지만 영향이 작음 |
| 기준 정보 겹침률 칸 | 파이프라인 단계 사이 겹침률로 들어감 |

## 8. 적용 결과 (2026-11-10)

### 8.1 만든 것

| 곳 | 내용 |
|---|---|
| 파일 구조 **v10** | `pipelines` · `pipeline_steps`(단계 = 파트, seq, overlap_rate) · `resource_types.pipeline_id`. 표 목록 한 곳([core/tables.ts](../core/tables.ts))에 등록해 이력 · 되돌리기 · 예전 구조 내보내기가 따라온다 |
| 엔진 | 리소스에 파이프라인이 있으면 그 단계 순서로 공정을 잇고, 파이프라인 밖 파트(공수가 남은 경우)는 맨 뒤. 겹침률 = 단계 값 → 파트 쌍 값 → 설정의 기본 값 순서([engine/stages.ts](../engine/stages.ts), 근거 `STEP`) |
| 기준 정보 › 공정 순서 · 파이프라인 | "기본(파트 표 순서)" 줄 + 파이프라인 카드(이름 · 쓰는 리소스 수 · 단계 더하기 · 단계 칩 끌기 · 단계 빼기 · 단계 사이 겹침률 · 지우기). 쓰는 리소스가 있는 파이프라인은 지울 수 없고, 공수가 있는 리소스가 쓰는 단계는 뺄 수 없다(먼저 옮기기) |
| 리소스 · 공수 표 | **파이프라인** 칸. 바꿀 때 새 파이프라인 밖 파트에 공수가 있으면 파트마다 옮길 곳(또는 지우기)을 고르는 창. 파이프라인 밖 칸은 잠금(빗금), 밖에 공수가 남아 있으면 주황 테두리 |
| 에셋 | 카드 체크리스트 · 파트 점 · 단계 고르기 칸이 그 에셋 리소스의 파이프라인 순서. 파이프라인 밖 "해당 없음" 파트는 감춤. 단계 앞 · 뒤(되돌림 확인)도 그 순서로. 보드에 **파이프라인 고르기**(모두 · 기본 · 파이프라인마다): 고르면 그 파이프라인 에셋만, 열 = 그 단계 |
| 현황판 · 작업 진척 | 단계 판정 · 배치 완료 · 진척 경고(앞 공정)를 리소스 파이프라인 순서로 |
| 데이터 점검 | A04 · P04를 파이프라인 단계로, E09(파이프라인 밖 파트에 공수) · E10(없는 파이프라인) 추가 |

### 8.2 설계에서 바꾼 점

| 설계(5절) | 만든 것 | 까닭 |
|---|---|---|
| 기존 파일을 옮길 때 같은 순서 목록끼리 파이프라인을 자동으로 만든다(5.2) | 만들지 않는다. `pipeline_id`가 비면 **기본(파트 표 순서)** — 지금과 똑같다 | 자동으로 생긴 이름 · 묶음을 사람이 다시 정리해야 하고, 비워 두면 계산이 그대로라 옛 도구 비교가 바로 같다. 필요한 리소스만 파이프라인을 고른다 |
| 파트 표 순서는 표시 순서로만(5.1) | 파트 표 순서 = **기본 파이프라인 순서**(파이프라인을 고르지 않은 리소스) | 위와 같은 까닭. 파이프라인을 고른 리소스에는 영향 없음 |
| 단계 겹침률을 비우면 "기본"(5.1) | 비우면 파트 쌍 값 → 설정의 기본 값 | 지금 파트 쌍에 넣어 둔 값을 잃지 않게. 화면에는 물려받은 값을 점선 · 흐리게 |
| 리소스에 파이프라인 없음 · 밖 파트 공수 = 오류(5.4) | 주의(E09 · E10) | 파이프라인 없음 = 기본 순서라 오류가 아니다. 밖 파트 공수는 입력에서 막고(새로 넣을 수 없음), 예전 값은 맨 뒤에 계산되므로 주의로 알린다 |
| 새 프로젝트 마법사가 기본 파이프라인을 자동으로(5.3) | 하지 않음 | "기본(파트 표 순서)"가 그 역할 |
| 현황판 단계 분포를 파이프라인별로 · 시뮬레이션 겹침률 대상 = 단계(5.3) | 아직. 현황판은 순서만 파이프라인을 따르고, 시뮬레이션 "겹침률 바꾸기"는 지금처럼 파트 쌍 | 쓰임을 본 뒤에. 단계 겹침률을 따로 적은 단계에는 시뮬레이션의 파트 쌍 바꾸기가 닿지 않는다(단계 값이 먼저) |
