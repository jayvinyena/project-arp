# 메뉴 배치 · 순서 · 사용 동선 최종 점검

2026-11-10 · 상태: **추천안대로 적용 완료** — 9절.

## 1. 방법

1. 비슷한 유형의 앱이 메뉴를 어떻게 나누는지 조사했다(2절).
2. ARP를 쓸 사람과 하는 일을 정리하고, 일마다 어떤 화면을 어떤 순서로 지나가는지 예측했다(3절).
3. 지금 메뉴 · 시작 화면 · 화면 사이 이동을 코드와 화면으로 확인해, 동선과 어긋나는 곳을 찾았다(4 · 5절).

## 2. 비슷한 앱 유형

| 유형 | 예 | 메뉴를 나누는 방식 | ARP에 주는 시사점 |
|---|---|---|---|
| 아트 · 게임 제작 관리 | Autodesk Flow Production Tracking(옛 ShotGrid) | 프로젝트 메뉴 = 만드는 대상(에셋 · 레벨 · 태스크) + 일정(간트). 사이트 전체 메뉴(사람 · 미디어)와 프로젝트 메뉴를 나눈다. 게임 템플릿은 레벨 · 에셋 중심 | **만드는 대상(에셋) 화면이 메뉴의 중심**이고, 일정 · 계획은 그 옆에 둔다 |
| 인력 · 일정 계획 | Runn · Float | 사람 기준 · 프로젝트 기준 계획 화면 + 보고서 + 설정. Runn은 "가정 프로젝트"로 시나리오를 따로 본다 | **계획 화면과 가정(시뮬레이션)을 가까이**, 설정은 맨 아래 |
| 일반 업무 앱 사이드바 설계 지침 | Linear · Notion 류, SaaS 디자인 가이드 | 자주 가는 2 ~ 3곳을 맨 위에, 나머지는 하는 일 단위의 적은 묶음으로. 깊이는 2단계까지. 만들기 · 관리 같은 동작은 이동 메뉴와 떼어 둔다 | **빈도순 + 하는 일 단위 묶음**, 파일 작업(저장 · 내보내기)은 메뉴와 분리(지금도 분리됨) |

공통점: 매일 보는 **현황 · 대상 목록**이 위, 가끔 하는 **계획 · 가정**이 가운데, 처음 한 번 하는 **설정 · 기준**과 **기록**이 아래다.

## 3. 사용자와 동선 예측

### 3.1 쓰는 사람

| 사람 | 주로 하는 일 | 빈도 |
|---|---|---|
| 아트 PM · 프로듀서 | 마일스톤 진행 확인, 늦는 곳 찾기, 물량 · 인력 결정, 보고 | 매일 ~ 매주 |
| 아트 리드 · 파트장 | 자기 팀(파트) 에셋 상태 갱신, 검수 · 수정 처리 | 매일 |
| 계획 담당(PM 겸) | 프로젝트 · 리소스 · 공수 · 인력 기준 정리, 업데이트 추가 | 처음 · 분기 |

### 3.2 동선(자주 하는 순)

| 동선 | 빈도 | 지나가는 화면(지금 메뉴 이름) | 지금 막히는 곳 |
|---|---|---|---|
| **A. 아침 확인** | 매일 | 파일 열기 → 제작 현황판 → (처리할 것) 에셋 카드 | 파일을 열면 **런칭 물량 설계**로 간다. 현황판까지 한 번 더 눌러야 한다 |
| **B. 팀 상태 갱신** | 매일 | 에셋 제작 현황(팀 거르기 · 보드) → 카드 → 상태 바꾸기 | 현황판에서 고른 마일스톤이 에셋 화면에 **이어지지 않아** 다시 고른다 |
| **C. 주간 반영 · 보고** | 매주 | 에셋(제작 리스트 엑셀 넣기) → 작업 진척(에셋 없는 리소스 수량) → 현황판(계획선 대비) → 보고용 엑셀 | 에셋 · 작업 진척 · 현황판이 메뉴에서 **계획 화면 사이에 섞여** 있다(현황판 → 런칭 → 업데이트 → 에셋 → 작업 진척) |
| **D. 계획 판단** | 결정할 때 | 업데이트 계획(늦는 업데이트) → 시뮬레이션(바꿔 보기) → 마감 맞추기(최소 변경) → 원본 반영 | 순서는 맞다. 단 "계획" 묶음 안에 현황 화면이 섞여 이 흐름이 끊겨 보인다 |
| **E. 공수 보정** | 분기 | 작업 진척(실투입 인·일) → 공수 보정 | 공수 보정이 기준 정보 맨 아래 쪽에 있어 작업 진척과 멀다(이건 "기준을 바꾸는" 일이라 기준 정보에 두는 것도 맞다 — 7절) |
| **F. 처음 설정** | 처음 한 번 | 새 프로젝트(또는 엑셀 가져오기) → 프로젝트 · 파트 · 리소스 → 인력 → 유형 템플릿 → 런칭 물량 → 업데이트 계획 | 새 프로젝트를 만든 뒤 어디부터 채울지 **안내가 없다**. 메뉴 순서(템플릿이 인력보다 위)도 설정 순서와 다르다 |
| **G. 문제 찾기 · 되돌리기** | 가끔 | 데이터 점검(빨간 숫자) → 고칠 화면 / 변경 이력 → 되돌리기 | 두 화면이 **기준 정보 묶음** 안에 있다. 성격이 다른 "기록 · 점검"이다 |

## 4. 지금 구조

| 묶음 | 메뉴(위 → 아래) | 성격 |
|---|---|---|
| 계획 | 제작 현황판 · 런칭 물량 설계 · 업데이트 계획 · 에셋 제작 현황 · 작업 진척 · 시뮬레이션 · 마감 맞추기 | 현황(3) + 계획(4)이 섞임 |
| 기준 정보 | 프로젝트·파트·리소스 · 유형 템플릿 · 인력 · 공수 보정 · 변경 이력 · 데이터 점검 | 기준(4) + 기록 · 점검(2)이 섞임 |
| (메뉴 밖) | 왼쪽 위: 넓게 보기 · 아래: 저장 · 파일 닫기 · 보고용 / 편집용 엑셀 내보내기 | 파일 작업은 메뉴와 떨어져 있어 좋다 |

- 파일을 열면 **런칭 물량 설계**가 처음 화면이다(메뉴 맨 위는 제작 현황판).
- 마일스톤(업데이트) 고르기가 **화면마다 따로**다: 현황판 · 에셋 · 작업 진척 · 시뮬레이션이 각자 기억하고, 화면을 옮기면 첫 업데이트로 돌아간다. 최소안 · 기본안 · 최대안 고르기만 모든 화면이 함께 쓴다.
- 같은 대상을 **"마일스톤"(현황판 · 에셋 · 가져오기)과 "업데이트"(업데이트 계획 · 작업 진척 · 시뮬레이션)** 두 이름으로 부른다.

| # | 문제 | 영향 | 크기 |
|---|---|---|---|
| 1 | "계획" 묶음에 현황 화면 3개가 섞여 있다 | 매일 쓰는 화면을 찾을 때 계획 화면 사이를 훑어야 한다(동선 A · B · C) | 큼 |
| 2 | 파일을 열면 런칭 물량 설계로 간다 | 매일 아침 한 번 더 누른다(동선 A) | 큼 |

| 7 | 새 프로젝트를 만든 뒤 "다음에 할 일" 안내가 없다 | 빈 프로젝트에서 어디부터 채울지 모른다(동선 F) | 중간 |
| 8 | 에셋 제작 현황과 작업 진척의 역할 구분이 메뉴에서 보이지 않는다 | 에셋이 있는 리소스는 작업 진척에서 고칠 수 없다는 것을 화면에 들어가야 안다 | 작음 |

## 6. 제안

### 6.1 메뉴 묶음 · 순서

| 묶음 | 메뉴(위 → 아래) | 바뀐 점 |
|---|---|---|
| **현황** | 제작 현황판 · 에셋 제작 현황 · 작업 진척 | 계획에서 떼어 맨 위로(매일 · 매주) |
| **계획** | 런칭 물량 설계 · 업데이트 계획 · 시뮬레이션 · 마감 맞추기 | 계획 → 가정 → 맞추기 순서가 끊기지 않게 |
| **기준 정보** | 프로젝트·파트·리소스 · 인력 · 유형 템플릿 · 공수 보정 | 처음 설정 순서대로(인력을 템플릿 위로) |
| **기록 · 점검** | 데이터 점검(배지) · 변경 이력 | 설정과 떼어 맨 아래 |

메뉴 15개 → 묶음 4개, 깊이 1단계 그대로. 묶음 이름 아래 줄 설명은 두지 않는다(메뉴마다 올리면 한 줄 설명이 이미 나온다).

### 6.2 처음 화면

파일을 열면 **마지막으로 본 화면**(이 브라우저 · 이 파일 기준)으로 간다. 처음 여는 파일이면:
- 에셋이나 작업 진척 기록이 있으면 → **제작 현황판**
- 없으면(계획 단계) → **런칭 물량 설계**
- 새로 만든 프로젝트 → 런칭 물량 설계 + 6.4의 안내

### 6.3 마일스톤 하나를 모든 화면이 함께

- 현황판 · 에셋 · 작업 진척 · 시뮬레이션 · 마감 맞추기가 **같은 "지금 마일스톤"**을 쓴다(최소안 · 기본안 · 최대안처럼). 한 화면에서 바꾸면 다른 화면도 바뀐다.
- 현황판의 "보드에서 보기 · 작업 진척에서 보기"도 그 마일스톤으로 연다.
- 이름은 하나로: **화면 글은 "업데이트"**(계획 · 계산 쪽 용어, 런칭도 업데이트의 하나)로 통일하고, 현황판 · 에셋 화면 고르기 이름표만 "업데이트(마일스톤)"으로 보여 팀 제작 리스트의 "마일스톤"과 이어지게 한다.

### 6.4 새 프로젝트 "처음 할 일" 안내

새로 만든(또는 비어 있는) 프로젝트의 현황판 · 런칭 화면 위에 접을 수 있는 안내 카드:
1. 프로젝트 · 파트 · 리소스(공수) → 2. 인력 → 3. 런칭 물량 → 4. (에셋을 관리하면) 제작 리스트 엑셀 넣기.
각 단계는 채워졌는지 자동으로 체크하고, 누르면 그 화면으로 간다. 모두 끝나면 사라진다.

### 6.5 에셋 · 작업 진척 역할 표시

작업 진척 메뉴 · 화면 머리에 "에셋이 없는 리소스의 완료 수량 · 모든 리소스의 실투입 인·일"이라고 적고, 에셋에서 자동 집계되는 줄은 지금처럼 잠금 + "에셋에서 집계" 표시를 유지한다.

## 7. 정할 것

| 질문 | 추천 | 다른 안 |
|---|---|---|
| 메뉴 묶음 | 6.1의 4묶음(현황 · 계획 · 기준 정보 · 기록 · 점검) | 3묶음(기록 · 점검을 기준 정보 아래 구분선으로) |
| 공수 보정 위치 | 기준 정보(공수 기준을 바꾸는 일) | 현황의 작업 진척 다음(실투입을 보는 일) |
| 처음 화면 | 마지막으로 본 화면, 처음이면 기록 유무로 현황판 / 런칭 | 늘 제작 현황판 |
| 마일스톤 공유 | 모든 화면이 하나를 공유 | 화면마다 따로(지금) |
| 용어 | "업데이트"로 통일, 현황 쪽 이름표만 "업데이트(마일스톤)" | "마일스톤"으로 통일(계획 · 계산 화면까지 바꿈) |
| 처음 할 일 안내 | 넣음(6.4) | 넣지 않음 |

## 8. 적용 범위(정하면)

- 메뉴 · 처음 화면 · 마일스톤 공유 · 용어: 화면 쪽만 바뀐다(파일 구조 · 계산은 그대로). 크롬 시험의 메뉴 순서 · 이동 검사를 함께 고친다.
- 처음 할 일 안내: 새 프로젝트 시험(e2e-new)에 단계 체크 · 이동 검사를 더한다.
- 확인: 동선 A ~ G를 크롬 시험으로 한 번씩 따라가 클릭 수를 전후 비교한다(예: 동선 A 2번 → 1번, 동선 B 마일스톤 다시 고르기 0번).

| 동선 | 전 | 후 |
