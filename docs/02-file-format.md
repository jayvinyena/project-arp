# 프로젝트 파일 형식 v1

## 1. 한 줄 요약

프로젝트 하나 = SQLite 파일 하나(`.arp`). 앱은 파일을 통째로 메모리에 읽어 쓰고, 저장할 때 통째로 다시 쓴다. 공유 드라이브 폴더에 두면 소수 관리자가 같이 쓸 수 있다.

## 2. 파일 표시

| 항목 | 값 | 쓰임 |
|---|---|---|
| 확장자 | `.arp` | 파일 선택 창 필터 |
| `PRAGMA application_id` | `1095913521` (`'ARP1'`) | ARP 파일인지 확인. 다르면 열지 않는다 |
| `PRAGMA user_version` | 구조 버전, 지금 `4` | 옛 파일을 새 구조로 바꿀지 판단 |
| `meta.saved_by_app` | 저장한 앱 버전 | 문제 추적 |

## 3. 열기

1. 파일 선택 창(크롬·엣지의 File System Access API)으로 파일을 고른다. 앱은 파일 핸들을 브라우저 저장소(IndexedDB)에 기억해 다음에 바로 연다.
2. 파일을 읽어 SQLite(WebAssembly)로 메모리에 올린다.
3. 확인한다.
   - `application_id`가 다르면 → "ARP 파일이 아닙니다"
   - `user_version`이 앱보다 크면 → "더 새 앱에서 저장한 파일입니다. 앱을 새로 고치세요" (열지 않는다)
   - `user_version`이 앱보다 작으면 → 구조 전환(아래 5절)
4. 편집 중 표시를 확인한다(아래 4절). 다른 사람이 편집 중이면 읽기 전용으로 연다.
5. 검증 규칙을 돌리고 결과를 데이터 점검 화면에 보여준다.

## 4. 저장과 겹침 방지

### 저장
- 바뀐 뒤 2초 동안 추가 변경이 없으면 자동 저장한다. 직접 저장(Ctrl+S)도 있다.
- 저장 한 번 = 변경 이력 한 묶음(`batch_id`). 시나리오 반영은 그 자체로 한 묶음이다.
- 저장할 때 `meta.data_version`을 1 올린다.
- 쓰기는 브라우저의 쓰기 스트림으로 한다. 브라우저가 임시 파일에 다 쓴 뒤 바꿔 끼우므로, 중간에 끊겨도 원래 파일이 깨지지 않는다.

### 편집 중 표시
- 편집 모드로 열면 `meta.lock_holder`(이름), `meta.lock_device`(이 브라우저의 표시), `meta.lock_heartbeat_at`(시각)을 적고 바로 저장한다. 같은 이름이라도 다른 PC(브라우저)가 편집 중이면 읽기 전용으로 연다(2026-11-05 전체 점검).
- 열려 있는 동안 5분마다 시각을 갱신한다.
- 다른 사람이 열 때 30분 안에 갱신된 표시가 있으면 "○○님 편집 중"과 함께 읽기 전용으로 연다.
- 30분이 지난 표시는 버려진 것으로 보고, 확인을 받은 뒤 넘겨받는다.
- 닫을 때 표시를 지운다.

### 저장 전 확인 (겹침 방지 2차)
1. 저장 직전에 파일을 다시 열어 마지막 수정 시각과 `data_version`을 읽는다.
2. 내가 연 뒤 바뀌었으면 덮어쓰지 않는다.
3. 대신 "다른 곳에서 바뀌었습니다"를 보여주고, 두 가지 중 고르게 한다: 다른 이름으로 저장, 또는 내 변경을 버리고 다시 열기.

동시 편집 병합은 하지 않는다. 소수 관리자가 번갈아 쓰는 용도이기 때문이다.

## 5. 구조 전환 (마이그레이션)

> 구현: [core/migrate.ts](../core/migrate.ts). 지금 구조는 **v4**(v1 → v2: 시나리오 동작 묶음·반영 기록, v2 → v3: 실적의 실투입 공수, v3 → v4: 에셋 관리 표 4개 — [20-asset-management.md](20-asset-management.md)). 자세한 내용은 [08-simulation.md](08-simulation.md).


- 앱에는 `v1 → v2`, `v2 → v3` 같은 단계별 전환 스크립트가 있다. 열 때 필요한 단계만 차례로 돈다.
- 전환하기 전에 원본을 `이름.v1.bak.arp`로 복사해 둔다(폴더 권한이 없으면 다운로드로 받는다).
- 전환은 한 트랜잭션이다. 실패하면 원본 그대로 연다.
- 전환한 파일은 사용자가 저장해야 디스크에 쓰인다.

## 6. 브라우저 저장소의 역할

IndexedDB에는 두 가지만 둔다.
- 최근 파일 핸들(다시 열기용)
- 마지막으로 연 파일의 사본(빠른 첫 화면용)

사본으로 먼저 그리고, 실제 파일을 읽어 `data_version`이 다르면 바꿔 그린다. 브라우저 데이터가 지워져도 잃는 것은 없다. 원본은 항상 파일이다.

## 7. 지원 범위

| 환경 | 동작 |
|---|---|
| 크롬, 엣지 (데스크톱) | 열기, 자동 저장, 편집 중 표시 모두 |
| 그 밖의 브라우저 | 파일 올리기로 열기, 다운로드로 저장 (자동 저장과 저장 전 확인 없음) |

## 8. 내보내기 · 가져오기

| 방향 | 형식 | 쓰임 |
|---|---|---|
| 내보내기 | `.xlsx` (표마다 시트 하나) | 보고, 백업, 다른 도구 |
| 내보내기 | `.arp` 사본 | 시나리오 공유, 보관 |
| 가져오기 | `.xlsx` (같은 구조) | 기존 시트 데이터 이전, 대량 수정 |

가져오기는 형식 오류(숫자 칸에 글자, 없는 파트 ID 등)만 거절하고 행 번호와 함께 알려준다. 값 규칙 위반은 그대로 들여오고 데이터 점검에 표시한다.
