# 전체 점검 (2026-11-05)

실제 사용 전에 0~7단계 코드를 다시 읽었다. 만든 사람의 눈으로만 보면 놓치기 쉬워서, 독립 점검 3개를 맡겼다. 맡긴 영역은 계산, 데이터, 화면·저장이다. 점검은 재현 가능한 문제만 보고하게 했다. 보고된 것은 모두 직접 확인하고 고친 뒤 검사로 고정했다.

## 계산

| 문제 | 영향 | 고침 |
|---|---|---|
| 시나리오 줄 하나가 넣을 수 없으면(키 겹침·형식 위반) 비교 전체가 멈춤 | 반영한 시나리오의 복제본, AI 비율 두 번, 9월 31일 같은 날짜에서 원본 열까지 계산 안 됨 | 줄마다 따로 얹고, 실패한 줄은 이유와 함께 건너뜀. 넣기는 같은 키가 있으면 덮어씀. 날짜는 달력에 있는 날만 받음 |
| 같은 칸에 인원·외주 동작을 두 번 넣으면 덮어씀(+2 뒤 +1 = +1) | 시나리오 결과가 작게 나옴 | 인원·외주 동작을 **더하기 값**(`{"add": n}`)으로 저장. 쌓이면 더해지고, 중간 동작을 빼도 나머지가 맞음. 원본 반영도 같음 |
| 출시일 없이 제작 완료 목표일만 있으면 런칭 거꾸로 계산이 항상 실패 | 최대 물량·필요 인원이 "0으로 줄여도 안 됨" | 판정 대신 날짜를 직접 비교 |
| 마감 맞추기의 물량 줄이기가 지금 물량 구간을 보지 않음 | 확장안에서 제안 안 됨, 최저안에서 헛계산 | 그 구간의 수량으로 판단. 선택 리소스만 줄여서 효과가 없을 때 "모든 리소스"도 함께 시도 |
| 가상 업데이트가 사용 안 함 리소스까지 넣음 | 같은 유형의 진짜 업데이트보다 길게 나옴 | 사용 중 리소스만(업데이트 만들기와 같게) |
| AI 비율이 다른 공수 프로필을 무시 | 합이 1이 안 돼 계산 막힘 | 그 밖의 프로필은 0으로 |

## 데이터

| 문제 | 영향 | 고침 |
|---|---|---|
| "만들기"를 되돌릴 때 그 뒤에 고친 물량·실적이 경고 없이 사라짐 | 고친 내용 손실 | 만들기·지우기는 같은 행의 모든 칸과 딸린 행(키가 "그 키\|…")까지 충돌로 보고 확인을 요구. 지울 때 딸린 행을 함께 남겨 다시 되돌리면 돌아옴 |
| 업데이트 지우기를 되돌려도 진행 실적이 안 돌아옴 | 실적·실투입 손실 | 지울 때 실적도 함께 남기고 되돌릴 때 넣음 |
| 지운 ID를 다시 씀(U001 지우고 만들면 다시 U001) | 지우기 되돌리기 실패, 이력이 다른 업데이트를 가리킴 | 변경 이력에 남은 ID까지 보고 새 번호를 매김 |
| 프로젝트에 오류가 하나라도 있으면 관계없는 되돌리기도 거부 | 되돌리기 불가 | 되돌려서 **새로 생긴** 오류만 봄 |
| 실적 엑셀의 "완료일"을 완료 수량으로 읽음 | 수량이 날짜 숫자(46000)로 바뀜 | 머리글을 이름 전체로 맞춤(공백·`_`·`-` 무시, 영어 머리글 포함) |
| 옛 시트에 중복 행·소수 순서·소수 템플릿 수량·없는 날짜가 있으면 가져오기 전체 실패 | 가져오기 불가 | 중복은 건너뛰고 보고, 정수 칸은 반올림, 없는 날짜는 빈칸. 같은 실적이 두 번이면 뒤의 값 |
| 엑셀 읽기: 빈 공유 문자열 `<si/>`, 빈 조각 `<t/>`, 날짜형 칸, 작은따옴표 속성 | 글자가 한 칸씩 밀리거나 읽기 실패 | 모두 처리 |
| 공수 보정 여러 개 적용이 한꺼번에가 아님 | 중간 실패 시 일부만 적용 | 한 묶음(하나라도 실패하면 모두 취소) |
| 조작된 파일의 변경 이력 칸 이름으로 다른 SQL 실행 가능 | 보안 | 실제 칸인지 확인 |
| 실적 기준일이 되돌리기에서 안 돌아옴, 리소스를 빼면 그 실적이 남음 | 작은 불일치 | 기준일도 이력에 남김, 리소스 빼기는 실적도 함께(되돌리면 함께 돌아옴) |

## 화면 · 저장

| 문제 | 영향 | 고침 |
|---|---|---|
| 파일을 열면(편집 중 표시 저장) 복구 사본이 지워짐 | 창이 꺼진 뒤 같은 파일을 다시 열면 고친 내용 손실 | 사본에 프로젝트 정보를 담고, **그 프로젝트에서 고친 것을 저장했을 때만** 지움 |
| 저장 충돌·오류 뒤 빠져나갈 길이 없음, 닫거나 떠날 때 경고 없음 | 충돌 뒤 고친 내용 손실 | 충돌 알림과 왼쪽 아래에 **다른 이름으로 저장**. 충돌·오류 중에도 복구 사본, 떠날 때 확인, 닫을 때 저장 실패면 확인 |
| 저장 중에 닫으면 닫은 파일이 되살아나 5분마다 편집 중 표시를 씀 | 동료가 계속 읽기 전용 | 닫기는 진행 중 저장을 기다림. 열기·닫기마다 세대를 바꿔 늦게 끝난 저장이 되살리지 않음 |
| 같은 이름이면 다른 PC에서도 편집 가능 | 두 곳에서 동시에 고쳐 충돌 | 편집 중 표시에 **기기 표시**(`lock_device`)를 함께 남겨, 같은 이름이라도 다른 PC면 읽기 전용 |
| 칸을 눌렀다 나오기만 해도 반올림한 표시값이 저장됨(0.875 → 0.88) | 값이 조용히 바뀜 | 보이는 글자를 고쳤을 때만 반영 |
| 거절된 값이 칸에 남음 | 화면과 계산이 다름 | 거절되면 원래 값으로 되돌림 |
| 다른 이름으로 처음 저장할 때 편집 중 표시가 없음 | 그 사이 동료가 편집으로 열 수 있음 | 저장 전에 표시를 씀 |
| 계산 스레드가 뜨지 못하면 화면이 멈춘 채 알림 없음 | 원인을 모름 | 기다리는 요청을 모두 실패로 끝내고 알림 |

## 시험 도구

- 크롬 시험은 `tools/e2e-all.mjs`가 한 번 빌드한 뒤 묶음 여러 개를 동시에 돌린다(기본 3개). 묶음마다 포트와 크롬 프로필이 다르다(`ARP_E2E_PORT`·`ARP_CDP_PORT`).
- 확인 창(떠나기 전 확인 등)은 자동으로 수락한다. 모든 요청에 60초 시간 제한을 둔다. 전에는 확인 창 하나에 시험이 끝없이 멈췄다.
