# 병렬 단계 검토

2026-11-10 · 상태: **적용함**(6절 추천안 1~5, 6번 "언제"는 바로) — 결과는 7절.

요청: "병렬로 진행되는 파이프라인은 겹침을 100%로 설정하면 되는지 확인" → "병렬을 추가한다면 어떤 방식이 좋을지 검토만".

## 1. 지금: 겹침률 100%

파이프라인 단계는 한 줄로 이어지고(앞 공정 하나), 겹침률 r이면 앞 공정이 (1 − r)만큼 진행된 다음 날 아침에 시작한다([04-engine-rules.md](04-engine-rules.md) 4절). 100%로 두면:

| 성질 | 100%의 동작 | 진짜 병렬이라면 |
|---|---|---|
| 시작 | 앞 공정이 시작한 **다음 영업일**. 단계마다 하루씩 밀린다 | 같은 날 |
| 완료 | 앞 공정보다 먼저 끝나지 않는다(완료 제약) | 따로 끝난다 |
| 앞 공정이 못 시작하면(인원 0 등) | 뒤 공정도 시작하지 않는다 | 상관없이 진행 |
| 갈래 | 표현 못 함(원화 다음에 모델링과 FX가 따로 가다가 애니에서 만나기) | 갈라졌다 합쳐진다 |

샘플 신규 캐릭터(원화 → 모델링 → 애니 → FX), 100%: 원화 11/05 · 모델링 11/06 · 애니 11/09 · FX 11/10 시작, FX 완료는 애니에 맞춰 2/03.

→ "하루 차이로 거의 동시에, 끝은 앞 공정에 맞춤"이면 100%로 충분하다. 공정끼리 서로 기다리지 않아야 하면 구조를 바꿔야 한다.

## 2. 병렬이 필요한 경우

| 경우 | 예 | 100%로 되나 |
|---|---|---|
| ① 갈라졌다 합쳐짐 | 원화 → (모델링 ∥ 이펙트 원화) → 애니 | 안 됨(한 줄로 이으면 이펙트 원화가 모델링을 기다림) |
| ② 처음부터 따로 | UI 디자인 ∥ 사운드(한 리소스 안) | 안 됨 |
| ③ 같이 시작 | 모델링 시작과 함께 리그 준비 | 거의(하루 늦음) |
| ④ 같이 끝냄 | 애니 끝날 때 FX도 끝냄 | 완료 제약으로 비슷 |

아트 리소스에서 흔한 것은 ①이다. ②는 ①의 특수한 경우(첫 묶음이 여럿)다.

## 3. 다른 도구

| 도구 | 방식 | 겹침 |
|---|---|---|
| Microsoft Project | 작업마다 앞 작업을 여러 개 연결. 연결 종류 4가지(끝-시작 FS 기본, 시작-시작 SS, 끝-끝 FF, 시작-끝 SF) — [Link tasks in a project](https://support.microsoft.com/en-us/project/link-tasks-in-a-project) | 연결마다 lead/lag. 앞 작업 기간의 %로도 적는다(-50% = 절반 겹침). ARP의 겹침률이 이것(FS + % lead)과 같다 |
| Flow Production Tracking(옛 ShotGrid) | 작업의 `upstream_tasks`에 앞 작업 여러 개, 연결마다 종류(finish-to-start-next-day, start-to-start, finish-to-finish 등) — [Task Dependencies](https://developers.shotgridsoftware.com/python-api/cookbook/tasks/task_dependencies.html), [Dependency Types in Task Templates](https://community.shotgridsoftware.com/t/dependency-types-in-task-templates/15031) | 연결 종류 + 날짜 오프셋 |
| ftrack | 작업 연결(Link) = 의존. 일정을 잡을 때 Workflow Schema로 자동 연결(끌 수 있음), Gantt에서 고침 — [Scheduling and Tracking](https://help.ftrack-studio.backlight.co/hc/en-us/articles/13129940399383-Scheduling-and-Tracking) | Gantt에서 날짜로 |

공통점: **앞 작업을 여러 개 둘 수 있다(그래프).** 연결이 없으면 따로(병렬) 진행한다. 다만 이 도구들은 사람이 작업 하나하나를 일정에 놓는 도구이고, ARP는 파이프라인 템플릿 하나로 리소스 · 업데이트마다 공정을 만들어 인원 한도 안에서 자동 배정한다. 템플릿을 쉽게 고칠 수 있는 단순한 모양이 더 중요하다.

## 4. 방식

| 방식 | 모양 | 표현 | 화면 | 엔진 | 파일 구조 |
|---|---|---|---|---|---|
| **A. 단계 묶음(추천)** | 단계를 묶음으로 쌓는다. 같은 묶음 = 병렬, 다음 묶음은 앞 묶음 **모두**를 기다린다 | ① ② ③ | 지금 칩 줄에서 칩을 세로로 쌓기("앞 단계와 함께") | 앞 공정 → 앞 공정 목록 | `pipeline_steps.with_prev`(0/1) 한 칸 |
| B. 단계마다 앞 단계 고르기(그래프) | 단계마다 "이 단계 다음"을 여러 개 고른다 | ① ② ③ + 엇갈린 연결(B는 A만, C는 A · B) | 연결선 그리기 · 고리 검사 | A와 같음 + 그래프 정렬 | 연결 표 새로(`pipeline_links`) |
| C. 연결 종류 더하기(MS Project식) | B + 시작-시작 · 끝-끝 · 날짜 차이 | 모두 | 연결마다 종류 · 차이 | 판정 규칙 4가지 | B + 종류 칸 |
| D. 100%의 뜻만 바꾸기 | 100% = 같은 날 시작 · 완료 제약 없음 | ③ 일부 | 그대로 | 판정 조건만 | 그대로 |

- **D는 고르지 않는다.** 한 줄 연결이라 ① ②를 못 하고, 앞 공정이 시작해야 하는 것도 그대로다. 옛 도구 비교(겹침 100% 규칙)도 깨진다.
- **C는 지금 규모에 넘친다.** 자동 배정 엔진에서 끝-끝 · 시작-끝은 "뒤 공정이 앞 공정을 늦춰야 하는" 경우가 생겨 하루씩 앞으로 배정하는 방식과 맞지 않는다.
- **B는 A로 못 하는 엇갈린 연결이 실제로 쓰일 때** 넘어간다. A의 묶음은 B의 특수한 경우라서, A로 만든 파일은 B로 옮길 때 그대로 바뀐다(묶음 사이 모든 쌍 = 연결).
- **A를 추천한다.** 아트 공정에서 흔한 ①을 덮고, 지금 칩 줄에 그대로 얹히며, 묶음이 하나뿐인 파일(지금 모든 파일)은 계산이 바뀌지 않는다.

## 5. A 단계 묶음 설계

### 5.1 규칙

- 묶음 k의 단계는 묶음 k−1의 단계 중 **그 리소스가 거치는 것 모두**를 앞 공정으로 둔다. 거치는 것이 없으면 그 앞 묶음으로 건너뛴다(지금 "건너뛴 파트" 규칙과 같다).
- 시작 판정: 앞 공정 **모두**가 겹침률 조건을 채워야 한다(각각 진행률 ≥ 1 − r, 어제까지 시작). 겹침률은 단계 값 → 파트 쌍(앞 공정마다) → 기본.
- 완료 제약: 완료일 ≥ 앞 공정 완료일 중 가장 늦은 날.
- 첫 묶음이 여럿이면(②) 모두 업데이트 시작일에 준비된다.
- 같은 묶음 안 단계끼리는 서로 기다리지 않는다. 같은 파트 인원을 나눠 쓰지 않으므로(파트가 다르다) 실제로 같은 날 시작할 수 있다.
- 리소스 · 업데이트의 완료일 = 마지막 묶음 단계들의 완료일 중 가장 늦은 날(지금 "마지막 공정"과 같은 뜻).

### 5.2 고칠 곳

| 곳 | 지금 | A 후 |
|---|---|---|
| 파일 구조 v12 | `pipeline_steps(pipeline_id, part_id, seq, overlap_rate)` | `with_prev INTEGER NOT NULL DEFAULT 0` — 1이면 앞 단계와 같은 묶음. 순서 끌기와 함께 움직인다. 옛 파일은 모두 0 = 지금과 같다 |
| 엔진 [stages.ts](../engine/stages.ts) · [schedule.ts](../engine/schedule.ts) | `predecessor: Stage` 하나, `successor` 하나 | `predecessors: Stage[]`, 다음 공정 목록. 아침 판정 · 완료 제약은 모두(최대)로 |
| 엔진 [index.ts](../engine/index.ts) 늦어진 이유 | 앞 공정을 한 줄로 거슬러 올라감 | 완료일을 정한 앞 공정(가장 늦은 것)을 따라감 |
| 결과 `predecessorPartId` | 하나 | 목록(`predecessorPartIds`) — 공정 표 · 엑셀 보고서 칸 |
| [pipelines.ts](../core/pipelines.ts) `partOrderFor` | 파트 목록 | 묶음 목록(`string[][]`). 한 줄이 필요한 곳은 펼쳐 쓴다 |
| 에셋 단계 판정 `stageOf` | 처음으로 안 끝난 파트 하나 | 처음으로 안 끝난 **묶음**. 카드에는 묶음 안 파트마다 상태 점 |
| 에셋 보드 열 | 파트마다 | 묶음마다(열 제목 "모델링 · 이펙트 원화"). 열로 옮기면 앞 묶음을 끝냄으로 — 지금 규칙을 묶음으로 |
| 현황판 · 작업 진척 경고(A04 · P04 "앞 공정보다 많이 끝남") | 앞 공정 하나와 비교 | 앞 공정 중 가장 적게 끝난 것과 비교 |
| 파이프라인 화면 | 칩 한 줄 | 칩 줄 + 세로로 쌓인 묶음. 칩 메뉴(또는 키보드)로 "앞 단계와 함께" 켜고 끄기, 끌어서 다른 칩 위에 놓으면 같은 묶음. 겹침률 % 는 묶음 사이에 하나(묶음 안 단계마다 다르면 칩에 작게) |
| 예전 구조 내보내기 · 옛 도구 | 한 줄 | 묶음을 표 순서로 펼쳐 내보내고 "병렬 단계는 한 줄로 바뀝니다" 알림 |
| 시뮬레이션 "겹침률 바꾸기" | 파트 쌍 | 그대로(파트 쌍 = 묶음 사이 각 쌍) |

### 5.3 확인할 것

- 묶음이 하나뿐인 파일: 계산 결과가 바이트까지 같다(지금 시험 · 옛 도구 비교 그대로 통과).
- 손 계산 예시: 원화 10일 → (모델링 15일 ∥ 이펙트 원화 6일) → 애니 8일, 겹침 0%. 모델링 · 이펙트 원화 11일째 함께 시작, 애니는 모델링이 끝난 다음 날(26일째) 시작.
- 성질: 묶음으로 바꾸면(한 줄 → 병렬) 늦어지지 않는다.
- 크롬: 칩 쌓기 · 풀기, 보드 묶음 열, 390px 넘침.

### 5.4 크기

엔진 반나절, 파일 구조 · 파이프라인 화면 하루, 에셋 보드 · 현황판 · 경고 반나절~하루, 시험 반나절. 모두 2~3일.

## 6. 정할 것

| 정할 것 | 추천 | 다른 안 |
|---|---|---|
| 1. 방식 | **A 단계 묶음** | B 그래프(엇갈린 연결이 실제로 있으면) |
| 2. 묶음 사이 시작 조건 | **앞 공정 모두**가 겹침률을 채움 | 앞 묶음 합친 진행률(공수 가중) — 짧은 공정이 묻힌다 |
| 3. 겹침률 칸 | **묶음 사이에 하나**(묶음 안 단계마다 따로 적을 수 있음) | 단계마다 따로만 |
| 4. 에셋 보드 열 | **묶음마다** | 파트마다(한 카드가 두 열에 보임) |
| 5. 겹침률 100%의 뜻 | **그대로**(옛 도구와 같음, 1절 동작을 화면 설명에 적음 — 적용함) | 같은 날 시작으로 바꾸기(D) |
| 6. 언제 | 실제로 병렬 리소스가 생길 때 | 지금 |

그동안은 "하루 차이 · 끝은 앞 공정에 맞춤"이 괜찮은 경우 겹침률 100%를 쓴다.

## 7. 적용 결과 (2026-11-10)

| 곳 | 만든 것 |
|---|---|
| 파일 구조 **v12** | `pipeline_steps.with_prev`(0/1). 옛 파일은 모두 0이라 계산이 그대로(옛 도구 비교 같음) |
| 엔진 | `predecessors` · `overlaps`(앞 공정마다 겹침률). 아침 판정 · 완료 제약 · 늦어진 이유를 앞 공정 모두로. 결과에 `predecessorPartIds` |
| 고치기 | `stepParallel`(앞 단계와 합치기 · 풀기, 합치면 묶음 첫 단계의 겹침률을 따름) · `groupOverlap`(묶음 단계 모두). `pipelineSteps`는 예전에 같은 묶음이던 이웃끼리만 묶음을 유지(묶음째 끌기 · 묶음 안 순서 바꾸기는 그대로, 빼거나 떼어 놓으면 풀림) |
| 파이프라인 화면 | 묶음마다 한 칸, 같은 묶음 칩은 세로로 쌓이고(점선 테두리) 같은 번호. 칩의 **∥** 로 합치기 · 풀기, 묶음은 첫 칩 손잡이로 끌기, 묶음 사이 겹침률 하나 |
| 에셋 | 단계 옮기기: 앞으로 = 앞 묶음만 완료, 뒤로 = 뒤 묶음만 대기(같은 묶음 다른 파트는 그대로). 되돌림 확인도 묶음 순서. 보드에서 파이프라인을 고르면 열 = 묶음("애니메이션 ∥ FX") |
| 작업 진척 · 데이터 점검 | "앞 공정보다 많이 끝남"(작업 진척 칸 · A04)은 앞 묶음 중 가장 적게 끝난 것과 비교, 같은 묶음끼리는 비교하지 않음. P04도 묶음 순서로 |
| 도움말 | 용어 "병렬 단계", 기준 정보 순서 |
| 옛 도구 내보내기 | 바꾸지 않음 — 옛 도구 양식에는 파이프라인 자체가 없다 |

- 단위 시험: 엔진 손 계산 두 개(5.3 예시 · 겹침 50%에서 느린 쪽 기다리기), 고치기 · 되돌리기, A04 · 작업 진척 · 에셋 단계 옮기기.
- 크롬: ∥ 로 합치기(같은 번호 · 묶음 사이 겹침률 하나), 보드 묶음 열, 390px 넘침 없음.
