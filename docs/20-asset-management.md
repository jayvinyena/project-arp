# 에셋 관리 (설계 v1.0)

2026-11-09 · 상태: **1단계 + 화면 재설계(리스트 · 보드 · 카드 창) 구현 완료** — 16 · 17절. 다음: 현황판, 2단계(배치별 완료 예측).

## 1. 목적

리소스 플래너는 지금 "업데이트 × 리소스 종류 × 파트"의 **수량**으로 공수와 완료 예정을 계산한다. 실제 제작은 수량이 아니라 **개별 에셋**(예: 동료쿠키 신규 "OO쿠키")으로 진행된다. 에셋 관리를 더해 다음을 한 도구에서 한다.

| 요청 | 이 문서의 답 |
|---|---|
| 항목별(마이쿠키 · 동료쿠키 · 트리처 등) 제작 진행 파악 | 분류 → 리소스 종류 → 에셋, 에셋마다 파트별 상태(5절) |
| 항목별 에셋 썸네일 | 에셋마다 대표 썸네일 1장, 프로젝트 파일 안에 작게 저장(8절) |
| 에셋 뷰어 | 나중(3단계). 이번 구조는 뷰어를 붙일 자리만 남긴다(10절) |
| 배치별 · 마일스톤별 제작 계획 | 마일스톤 = 업데이트, 배치 = 업데이트 안의 납품 묶음. 배치마다 완료 예측(6절) |
| 리소스 플래너와 연동 | 에셋 수 ↔ 물량, 에셋 상태 → 작업 진척, 엔진 예측 → 배치 판정(6절) |
| Jira 일감 연동 | 1단계는 이슈 키 → 링크. 나중에 상태 가져오기(9절) |

## 2. 정한 것 (2026-11-09 확인)

| 질문 | 결정 |
|---|---|
| "항목"은 어느 단계인가 | **분류 > 리소스 종류 > 에셋.** 항목 = 지금의 분류(동료쿠키 · 트리처 · 마이쿠키 의상 …). 에셋 하나 = 리소스 종류 아래 결과물 하나 = 물량 1개 |
| 배치 · 마일스톤 | 마일스톤 = 업데이트(M14 런칭 · Major 1 …). 배치 = 업데이트 안의 납품 묶음(마감일 있음). **배치별 완료 예측까지** 한다 |
| 상태는 누가 갱신하나 | **PM · 리드가 프로젝트 파일로.** 지금 구조(한 사람씩 편집, 서버 없음, 유지비 0) 그대로. 엑셀 통째 가져오기를 함께 준다 |
| 썸네일 저장 위치 | **프로젝트 파일 안 작은 썸네일.** 넣을 때 브라우저에서 줄여 저장 |

## 3. 전체 그림

```
계획(지금)                                   에셋 관리(추가)
──────────────────────────────────────      ───────────────────────────────────────────
업데이트(= 마일스톤)  M14 런칭                 └ 배치  1차 · 12/15 마감, 2차 · 1/30 마감 …
분류(= 항목)          동료쿠키
 └ 리소스 종류        동료쿠키 신규  물량 10    └ 에셋  OO쿠키, △△쿠키 … (최대 10개 → 물량과 대조)
                                                    └ 파트별 상태  원화 완료 · 모델링 진행 · 애니 대기 · FX 대기
                                                    └ 썸네일 1장 · Jira 키 · 메모

연동  ① 에셋 수 ↔ 물량(대조 · 맞추기)
      ② 에셋의 파트별 "완료" → 작업 진척의 완료 수량(자동 집계, 완료일 → 기준일)
      ③ 엔진이 배치 단위로 완료 예정 계산 → 배치 마감일과 비교(목표 안 · 빠듯 · 늦음)
```

운영 파일 기준 규모: 분류 8개 · 리소스 종류 23종 · 파트 4개(원화 → 모델링 → 애니 → FX), 진행 중 업데이트 3개의 목표 물량 합계 1,806개 → 에셋은 많아야 2천 개 안팎.

## 4. 데이터 모델 (파일 구조 v4)

새 표 4개와 설정 1개. 기존 표는 바꾸지 않는다(구조 전환은 `migrate.ts`로 v3 → v4, 기존 파일을 열면 자동).

| 표 | 행 하나 | 주요 칸 |
|---|---|---|
| `batches` | 배치 하나 | `batch_id`, `update_id`, 이름, 마감일(`due_date`), 순서(`sort_order`), 메모 |
| `assets` | 에셋 하나 | `asset_id`, `update_id`, `batch_id`(없으면 미배정), `resource_type_id`, 이름, 코드(선택), 포함 템플릿(`tier`: 최소안 · 기본안 · 최대안), 업데이트 안 순위, Jira 키, 메모, 취소 여부, 만든 시각 |
| `asset_parts` | 에셋 × 파트 | 상태(5절의 7가지), 시작일, 완료일, 리테이크 수, 담당(이름 글자, 선택), Jira 키(파트 작업 = Jira 이슈 하나, 선택) |
| `asset_thumbs` | 에셋 하나의 썸네일 | 이미지 바이트(WebP), 가로 · 세로, 바꾼 시각 |
| `meta` 키 추가 | — | `jira_base_url`(예: `https://<회사>.atlassian.net/browse/`). 계산 설정이 아니라서 `settings` 대신 `meta`에 둔다(구현 때 바꿈) |

- 에셋이 거치는 파트는 리소스 종류의 "거치는 파트"를 따른다. 에셋마다 빼는 파트(예: 재사용으로 원화 생략)는 상태 "해당 없음"으로 둔다(Flow · ftrack의 Omitted와 같은 뜻).
- 변경은 모두 변경 이력(`change_log`)에 남고 되돌릴 수 있다(지금과 같음). 썸네일 바이트는 이력에 넣지 않고 "썸네일 바꿈"만 남긴다.
- 시나리오는 1단계에서 에셋을 바꾸지 않는다(에셋은 실적 · 실물 기록). 배치 마감일 · 순서는 3단계에서 시나리오 대상에 넣을지 정한다.

## 5. 에셋 상태

제작 관리 도구들의 기본 흐름(Kitsu: TODO → WIP → WFA → Retake/Done, Flow: Ready to Start → In Progress → Pending Review → Final, 보류 · 생략 별도)을 따라 파트마다 다음 7가지를 둔다.

| 상태 | 뜻 | 완료 수량 | 칸 표시 |
|---|---|---|---|
| 대기 | 아직 시작 전 | — | 회색 |
| 진행 | 작업 중 | — | 파랑 |
| 검수 요청 | 리드 · 디렉터 확인 기다림 | — | 주황 |
| 수정 | 검수에서 돌려받음(리테이크) | — | 빨강 |
| 완료 | 승인됨 | **센다** | 초록 |
| 보류 | 멈춤(사유 메모) | — | 회색 빗금 |
| 해당 없음 | 이 에셋은 이 파트를 거치지 않음(재사용 등) | 센다(공수 0) | 빗금 |

- 완료 수량에는 **완료와 해당 없음**을 센다. 검수 요청은 완료로 보지 않는다(도구들 공통: "Done/Final"만 완료 통계에 들어감).
- 수정으로 돌아간 횟수(리테이크 수)를 에셋마다 센다. 리테이크가 잦은 리소스 종류는 공수 보정 화면의 참고 값으로 쓴다(재작업률).
- 완료로 바꾸면 완료일이 그날로 찍힌다(고칠 수 있음). 이 날짜가 작업 진척의 기준일이 된다.
- 앞 파트가 완료가 아닌데 뒤 파트가 완료면 데이터 점검에 "확인할 값"으로 띄운다(계산은 그대로, 지금 작업 진척의 A04와 같은 방식).
- 에셋의 진행률 = 끝난 파트 공수 ÷ 거치는 파트 공수 합(리소스 종류의 1개당 공수 사용). 분류 · 배치 · 업데이트로 합산한다.

## 6. 리소스 플래너와 연동

### ① 에셋 수 ↔ 물량

- 업데이트 × 리소스 종류마다 "등록 에셋 수 / 물량"을 보여 준다. 예: 동료쿠키 신규 **8 / 10**.
- 에셋에 포함 템플릿(`tier`)을 두면 템플릿별 물량을 에셋에서 셀 수 있다: 최소안 = 최소안 에셋 수, 기본안 = 최소안 + 기본안, 최대안 = 셋 다.
- 둘이 다를 때: **물량이 계획의 기준**이고 에셋은 그 안을 채운다. 다르면 표시만 하고, "물량을 에셋 수에 맞추기" 버튼(한 묶음 · 되돌리기 가능)을 준다. 반대 방향(물량만큼 빈 에셋 "이름 미정 1 · 2 …" 만들기)도 둔다. 에셋 목록을 처음 잡을 때 쓴다.

### ② 에셋 상태 → 작업 진척

- 업데이트 × 리소스 종류에 에셋이 하나라도 있으면, 그 줄의 완료 수량은 **에셋에서 자동 집계**한다(완료인 에셋 수, 기준일 = 가장 늦은 완료일). 작업 진척 화면에서 그 칸은 "에셋에서 집계"로 잠기고 누르면 에셋 화면으로 간다.
- 에셋이 없는 줄은 지금처럼 손으로 입력한다. 그래서 에셋 관리를 일부 항목에만 써도 된다.
- 엔진은 바꾸지 않는다: 완료 수량 · 기준일만 받으므로, 지난주에 고친 "기준일 다음 날부터 남은 일 · 이미 끝낸 몫 포함 진행률" 규칙이 그대로 적용된다.

### ③ 배치별 완료 예측 (엔진 확장)

- 지금 스테이지 = 업데이트 × 리소스 종류 × 파트. 이것을 **업데이트 × 배치 × 리소스 종류 × 파트**로 나눈다. 배치 하나의 수량 = 그 배치의 에셋 수(템플릿 구간 반영), 남은 물량(물량 − 등록 에셋 수)은 업데이트 안 "미배정" 묶음으로 마지막 배치 뒤에 둔다.
- 배정 순서: 업데이트 우선순위 → **배치 순서** → 지금 규칙(출시일 · 필수 먼저 · 순위 …). 같은 업데이트 안에서 앞 배치가 인력을 먼저 쓴다.
- 배치 결과: 완료 예정(그 배치 스테이지의 마지막 완료일), 마감일 대비 판정(목표 안 · 빠듯 · 늦음 · 못 끝냄), 늦음 영업일, 근거(가장 늦은 파트 · 리소스).
- 배치가 없는 업데이트는 결과가 지금과 **완전히 같아야 한다**(검사로 고정: 골든 파일 · 옛 도구 대조 그대로).
- 업데이트 계획 화면의 타임라인에 업데이트 아래 배치 줄(접기)과 마감일 표시를 더한다.

## 7. 화면 (1단계 — 16절 재설계로 바뀜)

**새 메뉴 "에셋"**(계획 묶음, 업데이트 계획과 작업 진척 사이).

| 영역 | 하는 일 |
|---|---|
| 위쪽 고르기 | 마일스톤(업데이트) · 배치(전체 · 1차 · 2차 · 미배정) · 상태 거르기 · 이름 찾기 |
| 분류 탭 | 마이쿠키 의상 · 동료쿠키 · 트리처 … 탭마다 "완료 32 / 120 · 27%" |
| 보기 전환 | **카드**(썸네일 격자, 카드 아래 파트 4칸 상태 점) / **표**(격자형 표: 에셋 × 파트 상태 칸, 기준 정보 표와 같은 디자인, 칸을 눌러 상태 바꿈) |
| 에셋 상세 패널 | 썸네일 넣기(끌어놓기 · 붙여넣기 · 파일 고르기), 파트별 상태 · 완료일 · 담당, 배치 · 포함 템플릿, Jira 키(링크 열기), 메모, 변경 이력 |
| 배치 보드 | 배치마다 열: 마감일 · 완료 예정 · 판정 · 진행률. 에셋을 고르고 "배치 옮기기" |
| 한 번에 고치기 | 여러 에셋 골라 상태 · 배치 · 담당 일괄 변경 |

기존 화면과 잇기:

- 런칭 물량 설계 · 업데이트 상세 패널의 물량 표에 "에셋 8 / 10" 열 → 누르면 그 리소스 종류의 에셋 목록.
- 작업 진척: 에셋에서 집계한 칸은 잠금 표시 + 이동 링크.
- 업데이트 계획: 배치 줄 · 배치 판정.
- 화면 안내(?)와 사용 설명서에 에셋 화면 추가.

## 8. 썸네일

- 넣을 때 브라우저에서 **긴 변 256px WebP(품질 0.8)** 로 줄여 저장한다. 에셋당 약 10–20KB, 2천 개면 20–40MB.
- 에셋당 대표 1장(1단계). 파트별 결과물 썸네일(원화 · 모델 · 애니 캡처)은 확인 후 2단계.
- 화면에는 보이는 카드만 읽어 그린다(가상 스크롤). 썸네일은 엑셀 내보내기에 넣지 않는다.

**위험: 저장 시간.** 지금은 저장할 때 파일을 통째로 다시 쓴다([02-file-format.md](02-file-format.md)). 파일이 30MB를 넘으면 공유 드라이브에서 자동 저장이 느려질 수 있다. 1단계에서 2천 개 규모 예시 파일로 저장 시간을 잰다. 기준(예: 1초)을 넘으면 ① 썸네일을 160px로 줄이거나 ② 썸네일만 파일 옆 동반 파일(`이름.arp-thumbs`)로 나누는 방법 중 하나를 고른다.

## 9. Jira

- **키를 두는 곳:** 제작 관리 도구의 Jira 연동은 **작업(에셋 × 파트) = Jira 이슈 하나**가 기본이다(Flow의 Jira Bridge 기본 동기화가 Task ↔ Issue). 그래서 파트마다 키 칸을 두고, 에셋 전체를 묶는 이슈(에픽 등)가 있으면 에셋에도 키 하나를 둔다. 둘 다 선택.
- **1단계:** 프로젝트 설정에 Jira 주소(Cloud `https://<사이트>.atlassian.net/browse/`, Data Center도 주소만 바꾸면 됨), 키 형식 검사(`ABC-123`). 키를 누르면 새 탭으로 이슈를 연다. 엑셀 가져오기 · 내보내기에 키 칸 포함.
- **나중(3단계):** Jira에서 상태 · 담당 · 마감일을 가져오기, 에셋에서 이슈 만들기. 브라우저에서 Jira API를 바로 부를 수 없어(CORS · 인증) 작은 중계(Cloudflare Workers 무료 범위)가 필요하다. 토큰 보관 · 사내 데이터가 중계를 지나가는 점은 보안 검토 대상이다.

## 16. 화면 재설계: 에셋 리스트 + 칸반 (2026-11-09 요청 · 추천안대로 확정)

**요청:** 지금 화면(숫자 칸 · 항목 탭 · 물량 대조 · 카드 · 배치가 한 페이지에 나열)은 방향이 맞지 않다. 가장 중요한 것은 "계획에 따라 지금 만들고 있는 에셋들의 정보 확인"이다.

- 에셋 리스트가 중심. 리스트에서 진행 상태가 보이고 바로 고칠 수 있다.
- 고치는 방식은 트렐로식 칸반: 카드를 다른 열로 끌어 상태를 바꾼다.
- 에셋마다 썸네일, Jira 링크(선택).
- 에셋을 누르면 트렐로 카드처럼 정보를 넣는다.

**판단: 가능하다.** 1단계의 데이터(에셋 · 배치 · 파트별 상태 · 썸네일 · Jira · 작업 진척 자동 집계 · 엑셀 · 변경 이력)는 그대로 쓰고, **화면 구성**과 **칸반 열 ↔ 파트별 상태 연결 규칙**, 카드 상세에 필요한 **작은 표 2개**(댓글, 링크)만 더하면 된다. 서버 없이(유지비 0) 끌어놓기 · 썸네일 · 2천 장 규모 모두 지금 구조로 된다.

### 16.1 바뀌는 화면 구성

```
에셋 제작 현황
┌ 위쪽 막대: 마일스톤 · 항목(분류) · 배치 · 담당 · 찾기 · [리스트 | 보드] · 에셋 더하기 · 엑셀
├ [리스트]  에셋 한 줄 = 썸네일 · 이름 · 항목/종류 · 제작 단계(칸 안에서 바꿈) · 세부 상태 · 담당 · 배치 · 마감 · Jira
│           줄 묶기: 항목 / 배치 / 단계, 정렬: 마감 · 단계 · 이름
├ [보드]    트렐로식 칸반. 열 = 제작 단계, 카드 = 썸네일 · 이름 · 세부 상태 배지 · 담당 · 마감 · Jira · 파트 점
│           카드를 다른 열로 끌면 상태가 바뀐다. 가로 줄(스윔레인)로 항목 · 배치 나누기(선택)
└ 카드를 누르면 → 에셋 카드 창(16.4)
보조 화면(탭): 배치 관리 · 물량 대조 — 지금 페이지의 해당 부분을 옮김
현황판(진행률 · 추이 · 처리할 것)은 별도 메뉴로(이전 답변의 제안, 이번 범위와 분리)
```

### 16.2 칸반 열 = 제작 단계 (핵심 결정)

트렐로 카드는 열이 하나지만, 에셋은 파트가 4개(원화 → 모델링 → 애니 → FX)라 상태도 4개다. 두 가지 방법이 있다.

| | A. 단계 보드 (추천) | B. 파트별 상태 보드 |
|---|---|---|
| 열 | 대기 · 원화 · 모델링 · 애니 · FX · 완료 | 대기 · 진행 · 검수 요청 · 수정 · 완료 (파트를 고른 뒤) |
| 카드 위치 | 지금 작업 중인 파트(앞에서부터 아직 끝나지 않은 첫 파트) | 그 파트의 상태 |
| 한눈에 | 에셋 전체가 어느 공정에 있는지 → **제작 현황 파악에 맞음** | 한 파트(예: 원화 리드)의 검수 대기열 관리에 맞음 |
| 세부 상태 | 카드 배지로(진행 · 검수 요청 · 수정 · 보류), 카드에서 바꿈 | 열 자체 |
| 참고 | 게임 아트 트렐로 보드의 흔한 형태(Concept → Modeling → … → Done) | Kitsu의 작업 종류별 칸반 |

추천: **A를 기본 보드**로, B는 보드 위쪽의 "파트별 보기" 전환으로 함께 둔다(같은 데이터, 열 만드는 규칙만 다름).

**A의 끌어놓기 규칙**(파트별 상태로 바꿔 저장 → 작업 진척 자동 집계 그대로):

| 카드를 옮긴 곳 | 파트별 상태 변화 |
|---|---|
| 앞 단계 → 뒤 단계(예: 원화 → 모델링) | 지나친 파트는 **완료**(완료일 = 오늘, 이미 있으면 그대로), 옮긴 열의 파트는 **진행** |
| 뒤 단계 → 앞 단계(예: 모델링 → 원화) | 옮긴 열의 파트는 **수정**(리테이크 1회), 그 뒤 파트는 대기로. 되돌리기 전에 확인을 묻는다 |
| 완료 열 | 거치는 모든 파트 완료 |
| 대기 열 | 모든 파트 대기(확인을 묻는다) |
| 그 리소스가 거치지 않는 파트 열(예: 코스튬 → FX) | 놓을 수 없음 표시, 다음 열로 안내 |

- 세부 상태(같은 열 안): 카드 배지를 눌러 진행 · 검수 요청 · 수정 · 보류로. 열 안 순서는 끌어서 바꾼다(우선순위).
- 여러 장 한 번에: 카드를 골라(체크 또는 Shift+클릭) 함께 끈다.
- 모든 이동은 변경 이력 한 묶음이라 되돌릴 수 있다. 끄는 동안 화면이 들썩이지 않게 열 높이 · 카드 크기는 고정한다.

### 16.3 리스트

- 기본 보기. 한 줄에 필요한 정보가 다 보이고 그 자리에서 고친다(단계 · 세부 상태 · 담당 · 배치 · 마감은 칸에서 바로).
- 줄 묶기(항목 · 배치 · 단계)와 정렬, 여러 줄 골라 한 번에 바꾸기.
- 격자형 표(기준 정보 표와 같은 디자인), 2천 줄도 보이는 줄만 그린다(가상 스크롤).

### 16.4 에셋 카드 창 (트렐로 카드 참고)

| 트렐로 | 에셋 카드 | 데이터 |
|---|---|---|
| 표지 이미지 | 썸네일(끌어놓기 · 붙여넣기 · 파일) | 있음(`asset_thumbs`) |
| 제목 · 목록 이름 | 에셋 이름 · 지금 단계 · 항목/종류 | 있음 |
| 라벨 | 항목 · 배치 · 포함 템플릿 · 세부 상태 | 있음 |
| 멤버 | 담당(파트별) | 있음(`asset_parts.assignee`) |
| 마감일 | 에셋 마감일(없으면 배치 마감일) | **추가**: `assets.due_date` |
| 설명 | 설명(여러 줄) | 있음(`assets.note`를 여러 줄로) |
| 체크리스트 | 파트 체크리스트: 원화 ✓ · 모델링(검수 요청) · 애니 · FX, 파트별 완료일 · 담당 · Jira | 있음 |
| 첨부 · 링크 | Jira 링크(에셋 · 파트), 그 밖의 링크(Confluence · 드라이브 등) 여러 개 | **추가**: `asset_links`(이름 · 주소) |
| 댓글 · 활동 | 댓글(작성자 · 시각) + 이 에셋의 변경 이력 | **추가**: `asset_comments`. 활동은 변경 이력에서 이 에셋 것만 |

파일 구조는 v5로 한 단계 더(표 2개 + 칸 1개 추가, 자동 전환). 댓글은 파일을 편집 중인 사람 이름으로 남는다(지금 구조는 한 번에 한 사람 편집).

### 16.5 지금 페이지에서 바뀌는 것

| 지금 | 바뀜 |
|---|---|
| 숫자 칸 4개 · 항목 탭 진행 막대 | 위쪽 막대의 거르기 옆 작은 요약 한 줄로 줄이고, 자세한 숫자는 현황판(별도 메뉴)으로 |
| ② 물량 대조 | 보조 탭 "물량 대조"로 |
| ③ 에셋 카드 / 표 | **리스트 / 보드**로 바꿈(보드 = 칸반) |
| ④ 배치 | 보조 탭 "배치"로 |
| 상세 패널 | **에셋 카드 창**(16.4)으로 넓힘 |

### 16.6 확인이 필요한 것

| # | 질문 | 추천 |
|---|---|---|
| 1 | 칸반 열: A 단계 보드 / B 파트별 상태 보드 / 둘 다 | A 기본 + B 전환 |
| 2 | 카드 창에 댓글 · 활동을 넣을지 | 넣는다(트렐로의 핵심 기능, 파일 안에 저장) |
| 3 | 에셋 마감일을 따로 둘지(배치 마감일과 별도) | 둔다(비우면 배치 마감일) |
| 4 | 현황판(진행률 · 추이 · 처리할 것)은 이번에 함께 할지 | 이번은 리스트 + 보드 + 카드 창, 현황판은 다음 |

### 16.7 순서 (확정 후)

1. 파일 구조 v5(마감일 · 링크 · 댓글), 단계 이동 고치기(`moveStage`: 16.2 규칙을 한 묶음으로) · 검사
2. 리스트 보기(격자형, 칸에서 고치기, 묶기 · 정렬 · 여러 줄 고치기)
3. 보드 보기(끌어놓기 · 여러 장 · 열 안 순서 · 세부 상태 배지 · 놓을 수 없는 열 표시)
4. 에셋 카드 창(표지 · 라벨 · 체크리스트 · 마감 · 링크 · 댓글 · 활동)
5. 배치 · 물량 대조 보조 탭으로 옮기기, 크롬 시험(끌어놓기 → 작업 진척 반영 · 되돌리기), 화면 캡처 · 문서
